# 视角转换定律（读者视角 > 发布者视角）

> 2026-08-30 实证调研：小红书/B 站「AI 任务管理」场景同题对照。同场景下直接产品介绍体 87-104 赞，痛点/教程体 1428-9841 赞——**差距 100 倍，胜负手在视角**。任何稿子起草前先过本文件，标题和开头不过关就重写。

## 一、视角矩阵（旧→新）

| 发布者视角（旧） | 读者视角（新） | 实证锚点 |
|---|---|---|
| 「我做了 X」宣告 | 「不要再用 Y 了」痛点否定 | 小红书 9841 赞/1.5万收藏 |
| 功能列表 | 「如何 <读者目标>」how-to | B站 136k 分（如何用 Codex 管理长期项目） |
| 求体验求反馈 | 转述+亲测：「刷到…我试了试」 | 小红书 1428 赞/2269 收藏 |
| 自卖自夸 | 诚实折扣：主动说 1-2 条局限 | 1428 样本「甚至有点过度挑刺」 |
| 产品是主角 | 产品藏在手段位（教程里的工具） | how-to 体通则 |
| 一次发完 | 干货帖攒信任 ⇄ 产品帖收割，交替 | 账号=信任资产负债表 |

## 二、操作定律

1. **标题=读者的痛点/目标/疑问，绝不出现「我做了/我开发了」**。标题是唯一的 100 倍杠杆。
2. **开头降姿态三板斧**：转述（学来的）、亲测（我试了）、踩坑（我以为…实际…）。身份是「刚好先走一步的同路人」，不是卖家。
3. **产品露出在手段位**：正文推进到「怎么做」时工具自然出现，一段带过+一个链接，不重复推销。
4. **诚实折扣必配**：主动写 1-2 条真实局限（解析偶尔跑偏/依赖外部 LLM/界面还糙）。没有缺点的内容比有缺点的内容可信度低。
5. **为收藏设计**：可复用的命令块/清单/prompt 模板让读者收藏。工具内容收藏率>点赞率是核心指标（1.5万收藏>9841 赞的样本）。
6. **内容分层交替**：纯干货帖（零产品）与产品帖（轻露出）按 ≥2:1 交替，账号信任是先攒后花的资产。
7. **平台话术适配**：小红书结尾可加「无意推广/心得分享」防限流声明；tag 铺产品词+场景词+活动词三层。

## 三、ai-todo 内容选题矩阵（读者视角版，按手法分）

| 手法 | 选题 | 首发平台 |
|---|---|---|
| 痛点否定 | 「不要再用对话窗口管 Claude Code 的任务了」 | 小红书/掘金 |
| how-to | 「如何让 Claude Code 记住你的长期任务」 | B站/掘金/知乎 |
| 高级用法 | 「让 agent 自己跟进自己的任务：我配了一套每日自动总结」 | 掘金/V2EX |
| 场景叙事 | 「我睡觉的时候，它在跟进我的 20 个任务」 | 小红书 |
| 复盘心得 | 「给 AI 做任务管理工具，踩过的 N 个坑」（Boss Fight 素材复用） | dev.to/掘金 |

（产品贴数量有限的手法=优先 how-to 和高级用法：可持续产出且转化路径自然。）

## 四、现有稿子审视结论（2026-08-30）

- V2EX 稿：**维持**——分享创造节点本身是产品发布语境，社区预期如此；开头已是痛点起手，不生硬。
- 掘金稿：标题可升级为读者视角（候选：「Claude Code 的任务清单会话结束就没了？我把任务状态交给 agent 自己管」），发布前定稿。
- dev.to 英文稿：标题「I built a todo app for Claude Code first」是宣告体但 dev.to #showdev 语境接受；保留，观察数据。
- 渠道语境优先：定律不是 everywhere——**发布类社区（V2EX 分享创造/dev.to showdev/Show HN）接受宣告体**，内容消费社区（小红书/B站/知乎/掘金首页）必须读者视角。两套并存，按渠道选。
