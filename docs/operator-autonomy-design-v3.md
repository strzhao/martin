## 0. 30 秒版

**v2 错在哪（一句话）**：v2 的问法已经对了（「改完谁审、怎么退、谁看得见」），但它把答案落成了**新机制**——只读 token 注入 + 回退点通道 + append-only 哈希链账本。三件都是新的需要维护的东西，而用户判定的根因是**指导不够**，不是机制不够。

**v3 换了落点**：把答案从机制移回指导。

```
发现缺口 → [fix] 卡上四问（第一性原理 / 已有基建 sweep / KISS 阶梯 / 剃刀）+「不修会怎样」
        → 修复流走每周批量议程（时间过滤假问题 + 同形并看逼出结构解法），流血中的除外
        → 红队只审「四问答得扎不扎实」（证据链完整性），不审路径白名单
```

**机械层归零**：git 已是回退 + 台账 + 留痕（reflog 实证 amend 可见 + public remote 外部锚），看板已是状态（事件全量表），既有钳夹已是校验（auto-gate / l2_ledger / rq / forge 单写方 / tests + mutation 自证），`.bak` 惯例已是数据面兜底（`contrib-data/` 不在 git）⇒ **v2 的三件套全删**，只读 token 降级为**风险登记册**一条（触发条件=首次注入痕迹）。

**今天 5 个缺口过四问**：修复流 **2 件**、won't-fix **2 件**（另 1 件判 `already-covered`、1 件根因转上游）、人门 **0 次**、**净新增零件 0 个**（`#1` −1 处吞失败形状，`#3` +1 个枚举词，相加为零）。v2 同一批是 4 件修复 + 1 账 1 verify 1 token 注入；v1 是「2 补丁 + 1 人拍 + 2 次零动作 + 6 道闸」。

**本设计自身零新建机制**——四问 = 卡模板栏目、红队 = 已有先例（板上 6 张 `深检 redteam` 卡 done）、议程 = 宪法 P9 既有 auditor + 既有报告通道、清单 = 看板一张卡、留痕 = git 提交说明。自证表见附录 B。

**诚实的代价**：v3 的动作数最少、零件增量为零，代价是**修复延迟**（议程最长一周，流血例外当班）与一个可反驳的赌注——「先扫已有基建 + 默认不修」能把误修率压到低于 v2。今天 5 件实测支持这个延迟（无一在流血，3 件已被兜底）；若一周内出现一次无兜底的真实损失，即收紧节奏（§6.3）。

## 1. 诊断：v2 的两处错位与根因

### 1.1 v2 的两处错位（实证）

| v2 的形态 | 实际后果 | 实证 |
|---|---|---|
| **机械层三件套**（只读 token 物理闸 / 回退点通道 / append-only 决策账 + 哈希链） | 每件都是新的维护面：一本账 + 一个 `verify` 命令 + 一个 token 注入 seam + 周报对锚环节 + 机械抽签 | 用户裁定「太复杂」；且它逆着 AI Native 宪法的终态走（宪法定 `scripts/contrib ≈ 4 文件`、账本 3 本；三件套会变成 6 文件 + 5 账本） |
| **判断发生在事后**（红队七问：真库对拍 / 回退可达 / 爆炸半径…） | 卡上不要求先做「已有基建 sweep」⇒ 缺口一来就进入「修」的默认路径；红队才第一次问「证据扎不扎实」，此时成本已付 | v2 §8 演示：5 个缺口 → 4 件修复，其中 2 件本可被已有基建/知识层吸收（本文件 §9 回测） |

### 1.2 根因（用户判断，本版地基）

**「问题不是修或者不修，而是怎么修复。根因是 AI 的上下文和指导不够——如果 AI 知道 git、被引导优先看已有基建，就可以了。」**

⇒ 缺的是**指导**：把「先看已有基建」变成卡上的**必答栏目**（不写完不能进修复流），而不是把「修复」这件事包进新机制。这与 AI Native 宪法 §1 的判据一致——需要「毫不动摇、错了必须拒绝而不是变通」的才进代码层（`contrib-ops-ai-native-design.md:13`）；「怎么修」是判断，归 AI，但判断需要脚手架。

### 1.3 三条实证：为什么「机制化」会反噬

| # | 实证 | 说明 |
|---|---|---|
| a | **v1 的独立决策账 + 哈希链** | 走一遍 Q2（已有基建 sweep）30 秒内被 git 干掉——整件删除。教学案例见 §5 |
| b | **宪法终态**（`contrib-ops-ai-native-design.md:68-81`） | 账本 9 → 3 本、`scripts/contrib` 16+ → ≤4 文件；v2 的三件套方向相反 |
| c | **补丁熵的真实形态** | 不是「修得太多」，是「没有收敛压力 + 默认动作是修」：`run-watch` 每个缺口加一段、长到 38KB/5 段骨架后只能整体退役；09-13 E 波近 12 次提交 **+3604 / −20475 = 净删 16871 行**（`git log --numstat` 实查） |
| d | **v2 的红队七问里第 2/3/5 问其实已经在问同一件事**（证据扎不扎实） | v3 把它**前置**成卡上栏目，红队只做复核：同一判断，成本从「一轮红队」降到「填三行字」 |

## 2. 四原则 → 本设计的形态

| # | 原则 | 它问什么 | 落到本设计的形态 | 反过来说（被删掉的形态） |
|---|---|---|---|---|
| 1 | **第一性原理** | 问题的最小事实是什么？修的是根因还是症状？ | **Q1** + 「不修会怎样」（默认动作 = 不修，修需要论证） | 把「发现缺口」直接当「该修」（v1/v2 的隐含默认） |
| 2 | **AI First** | 这个判断能不能交给 AI？ | 判断全归 AI；机械层归零（宪法判据：只有「错了必须拒绝」的才进代码） | v2 三件套 = 把判断写成机制；v1 = 把信任写成许可表 |
| 3 | **KISS** | 能不能不新建？能不能更小？ | **Q2 已有基建 sweep** + **Q3 阶梯**（删 > 配置 > 一行 > 一段 > 新建） | 新建账本 / 校验器 / 哈希基线 / 只读 token 注入 |
| 4 | **剃刀** | 假设最少、零件最少的是哪个？ | **Q4**（最少假设 + 净零件计数）+ 每周议程的**同形并看**（N 件同形 ⇒ 一个结构件，不是 N 个补丁） | N 个缺口 = N 个补丁（v1 靠限速挡，v2 靠红队挡，都不解决默认路径） |

**设计题眼**：v3 不是「更松」也不是「更严」，是**把判断的位置换到了成本最低处**——事前（卡上三行字）而不是事后（红队 / 人门 / 周报审计）。指导的形态是文字，文字的维护成本是零。

## 4. 核心：修复判断四问（`[fix]` 卡模板）

### 4.1 卡模板（可直接粘进 body）

```
标题：[fix] <一句话缺口>          （禁「优化 / 重构 / 加固 / 完善」类无缺口标题）
──────────────────────────────────────────────────────
Q1 第一性原理
   最小事实：<一行代码 / 一条命令级别的事实，无「可能 / 大概」>
   症状→根因链：症状 = <观测> → 层1 = <证据> → 根因 = <最小事实>   （≤3 层）
   复发判据：修完后，下一次同形缺口还会不会以另一种形状复发？<是 / 否 + 理由>
Q2 已有基建 sweep（逐项点名，附命令 + 输出要点；不许「我知道有」）
   git 覆盖：<命令> → <输出要点>          ⇒ 这件要回答的问题是否已被 git 答了？
   看板覆盖：<命令> → <输出要点>          ⇒ 状态 / 历史是否已可读？
   既有钳夹覆盖：<命令> → <输出要点>      ⇒ 校验是否已有（测试 / mutation / 对拍）？
   .bak / 数据面：<现状>                  ⇒ 写回是否有兜底？
   知识层覆盖：<skill 节> → <是否已吸收>  ⇒ 该口径是否已写进 skill？
   结论：已覆盖 <X>；未覆盖 <Y>（这就是这件要修的全部）
Q3 KISS 阶梯（每级必须答「为什么这级不行」，要证据不要感觉）
   能删不改？  <候选动作> → <不行，因为…>
   能改配置？  <候选动作> → <不行，因为…>
   能改一行？  <候选动作> → <不行，因为…>
   ⇒ 落到哪级：<删 / 配置 / 一行 / 一段 / 新建>
Q4 剃刀
   最少假设：能解释全部观测的假设集合 = {…}   （附「多余假设为什么被排除」）
   新增零件计数：脚本 <n> / 文件 <n> / 字段 <n> / 常量 <n>；删除抵扣 <n> ⇒ 净 <N>
   回退：<具体命令>（仓内 = git revert <sha>；数据面 = cp .bak-<ts> <file>）；跑过吗？<是 / 否>
   净 N > 0 时逐项答：为什么零新增不行？<…>
不修会怎样（默认动作 = 不修，修复需要论证）
   可计量损失：<次数 / 延迟 / 一次性成本，带数字>      不可计量损失：<…>
   已兜底手段：<巡检 / 契约 / 口径> ⇒ 现有兜底是否已把损失吸收？<是 / 否>
──────────────────────────────────────────────────────
bleeding: yes|no        （yes 必须同时满足 §6.3 三条判据，否则按 no 处理）
verdict: fix | won't-fix | upstream | already-covered
new_parts: <净零件数>   （红队核对项）
```

### 4.2 四问的判据（给红队用，每条一句话）

- **Q1 判据**：最小事实能**一条命令复现**吗？「换个写法就好了」= 症状级 ⇒ 打回。今天反面实证：09-13 14:13 首诊「静止态必失败」→ 15:06 修正为「竞态型」，一次单点观测足以把修法带偏（全量换读法 vs 只改参数）。
- **Q2 判据**：**答不出「查过了」= 打回**。逐项点名是为了防自由回忆——「AI 知道 git」不等于「AI 会说 git 已经覆盖了这个需求」。sweep 的目的不是「查了就不修」，是**查了才知道该修多小**。
- **Q3 判据**：从上往下走，每级「不行」都要有证据；跨级必须有理由。序：**删 > 配置 > 一行 > 一段 > 新建**。
- **Q4 判据**：零件计数含新增脚本 / 文件 / 字段 / 常量（周流程也算）；删除抵扣；红队拿数字核对。

### 4.3 四种归宿 + 默认动作

| verdict | 去向 | 记录处 |
|---|---|---|
| `fix` | 修复流（每周议程批量处理，§6.2） | 卡 + 议程 |
| `won't-fix` | **已知缺陷清单**（§6.1） | 清单卡一行（登记日 + 缺口 + 「不修会怎样」+ 升级条件） |
| `upstream` | 轴一（issue-first → L2）——本职 KPI，不被人门挡住 | 卡 + rq |
| `already-covered` | 直接关（知识层/基建已吸收，不改代码） | 卡上写清是哪条口径 / 哪一个基建项 |

**默认动作 = 不修**：无「不修会怎样」论证的缺口不进修复流。

## 5. 教学案例：v1 的独立决策账 + 哈希链，走一遍四问（回测）

> 这件是 v1 §4.3 的核心资产，v2 原样保留并加了哈希链。用 v3 的四问回测，它在 Q2 就被拦下。

**Q1 最小事实**：我们要回答的是「谁在什么时候改了什么、为什么、怎么退」——最小事实 = 这三问的答案现在存在哪里。

**Q2 已有基建 sweep**（三项命令即可结案）：

| 项 | 命令 | 输出要点 |
|---|---|---|
| git | `git log --numstat` | 改动 + 作者 + 时间 + 提交说明里的理由（实证同 §3.1 表格） |
| git | `git reflog` | `fc46a71 HEAD@{0}: commit (amend)` / `3033c0d HEAD@{1}: commit` ⇒ **amend/重写留痕**（原版本仍在 reflog） |
| git | `git remote -v` | `origin git@github.com:strzhao/martin.git` ⇒ 远端副本 = 外部锚 |
| 看板 | `select … from tasks/task_comments` | 决策情境（为什么这么改）在卡与评论线程里 |
| 知识层 | skill §8 判例库 | 已吸收的规则性条款在这里 |

⇒ **已覆盖 100%，未覆盖：无**。

**Q3 KISS 阶梯**：能删不改？——这件本身就是「新建」（一本 jsonl + 一个 `verify` + 每行 `prev` + 每周对锚）⇒ 三级全否，落到**新建**。

**Q4 剃刀**：假设集合 = {「git 不能提供不可否认性」}——该假设**被排除**（reflog + 远端副本提供同一强度；且篡改者 = AI 自身时，哈希链由 AI 自己写、自己验，边际强度为 0）。零件计数 = 脚本 1 + 文件 1 + 字段 2（`prev`/`review_tier`）+ 周流程 1 = **净 5** ⇒ 必须证明「零新增不行」——它答不了任何问题（唯一边际价值是篡改留痕，已被 git 覆盖）。

**verdict: `already-covered`**（整件删除；只保留一条文字约定：**修复的提交说明必须写 why**）。
**不修会怎样**：损失 = 每周多读一本账、多跑一个 `verify`、多维护一份字段契约（**负收益**，即「不建」才是收益）。

**这个案例的意义**：v1/v2 用 1 本账 + 1 个 append/verify 脚本 + 2 个字段契约 + 1 条周流程建的东西，Q2 三行命令就答完了。v2 保留了它、还加了哈希链；v3 删掉它——同一个结论，靠的不是更强的机制，是**「先 sweep 已有基建」这一条指导**。这条指导今天已经写在 skill 里（§8 判例：引用前先实查可达性），v3 只是把它抬成卡上必答栏。

## 6. 防「多做」两条（保留自 09-13 晚会话共识）

### 6.1 默认不修：每件先过「不修会怎样」

- 候选缺口先答「不修会怎样」（具体损失）；**答不出具体损失 = `won't-fix`**，登记进**已知缺陷清单**。
- 清单的家 = **看板上的一张常驻卡**（零新文件、零新脚本；板 = 记忆）：每项一条评论 = 登记日 + 缺口 + 「不修会怎样」的答案 + **升级条件**。
- 清单不是坟场：每项带升级条件（「若 X 发生则升修复流」），议程每周过一遍。**时间过滤假问题**：登记 ≥7 天仍无人被现实追债的件，多半是假问题（自己消失了）；真问题会自己回来敲门——今天 5 个缺口里 3 个正属「登记了但还没被现实追债」的形态。
- 这一条同时改写了 AI 的**默认行为**：从「发现缺口 = 修」改为「发现缺口 = 登记 + 论证」。

### 6.2 每周批量议程（修复不断线，但不即兴）

- **节奏**：班次内只做感知 / 登记 / 兜底（巡检）；**修复动作集中在每周一次议程**。
- **议程的家**：宪法既有的 **P9 每周 fresh-context auditor**（`contrib-ops-ai-native-design.md:26,89`）+ 既有报告通道（cron `69dda6b658de` 开源运营日报 09:12 / contrib digest）——**零新角色、零新 cron**。
- 议程固定两件事：
  1. **时间过滤**：只处理登记 ≥7 天、且「不修会怎样」的答案已随时间变硬（真发生过一次）的件；
  2. **同形并看**：候选按 shape 摆在一起（一行一件、同列可扫），N 件同形 ⇒ 逼出**结构解法**（一个抽象 / 钳夹 / 参数 / 枚举），产出必须回答「这几件合并成什么、被取代的是哪些」——**收敛而不是打 N 个补丁**。

### 6.3 流血例外（不走议程，当班即修）

三条判据必须**同时**满足，缺一按 no：

1. 损失**正在发生**（不是「将来会」）：正在丢数据 / 正在对外误报 / 正在白烧配额 / 正在阻塞在飞 KPI 资产；
2. **无过程兜底**：巡检 / 契约 / 口径都盖不住（有兜底的一律等议程）；
3. 修法在 KISS 阶梯的**上三级**（删 / 配置 / 一行）——需要「新建」的一律等议程（新建是结构判断，不该在班内即兴做）。

卡上落 `bleeding: yes` + 三条逐条证据；周报列流血例外数；auditor 每周审「有没有把不流血的叫流血」。

### 6.4 诚实的代价（可反驳承诺）

v3 把修复延迟从「当天」拉到「最长一周」。**若一周内出现一次真实损失（可指认、无兜底可吸收），即判议程太慢 ⇒ 收紧为「流血判据放宽 + 议程改每日」。** 今天 5 个缺口的实测支持这个延迟：无一在流血，且 3 件已被兜底（§9）。

## 7. 红队：审「四问答得扎不扎实」，不审路径白名单

### 7.1 三条硬纪律保留（结构性 fresh context 的充分条件）

1. **换进程**：独立 agent 进程/会话（不是同 context 自我复核）。
2. **只给产物**：输入 = 卡 + 产物 + 证据 + 原则；**不给**修复者的论证叙事。
3. **换模型族**：红队卡固定与修复方不同的 `provider`。

先例是**已在跑**的形态，不是纸面：板上 `深检 redteam` 卡 6 张 done（`t_9806a0b2` / `t_eb5a8969` / `t_e3e4fef4` / `t_7a59ef39` / `t_e06cbc66` / `t_b8043d17`）；结构性 fresh-context 的机制锚 `hermes-contribution.md:227`（「两次独立 `claude -p` 进程 = 结构性 fresh-context」）。**注**：v2 引用的 `.claude/skills/contrib-watch/SKILL.md:119` 已随 E 波退役（目录已不存在），本版更正为上面两个活锚。

### 7.2 审法（逐问；红队必须**拿命令重跑**，不接受转述）

| 问 | 红队要做的 |
|---|---|
| Q1 | 最小事实能否一条命令复现？对照实验是**同刻**的吗？（单点观测会把修法带偏——今天 14:13→15:06 的实证） |
| Q2 | **重跑** sweep 的每条命令，逐项核对「已覆盖 / 未覆盖」；发现漏项（尤其漏掉「git 已覆盖」）= `REBUT` |
| Q3 | 每级「为什么不行」是否有证据；有没有跨级（能删的去改一行、能一行的去新建） |
| Q4 | 零件计数是否漏计（新增常量 / 字段 / 周流程都算）；净 >0 时「为什么零新增不行」是否成立；回退命令是否真跑过 |
| 不修会怎样 | 可计量损失有没有数；兜底是否真的盖得住 |

### 7.3 红队**不审**什么

路径白名单、diff 行数上限、参数方向表——这三样是 v1/v2 的许可表面，v3 已删。红队审它们 = 把判断换回枚举（正是用户否掉 v1 的理由）。

### 7.4 红队自己也要过 KISS

红队卡 = 既有 kanban 卡（`[redteam]`）+ 独立 `claude -p` 进程，**零新建 profile、零新建 lane**。判词三态保留：`GO` / `GO-WITH-FIXES`（列必修项）/ `REBUT`（含理由）；`REBUT` 不上报给人，回修复者重做或弃。

## 8. 周报健康指标（人读 30 秒）

### 8.1 四个数（+ 一个辅助口径）

| 指标 | 口径 | 健康方向 | 基线（09-13 实查） |
|---|---|---|---|
| **发现/动作比** | 本周新登记缺口数 ÷ 本周修复动作数 | **走低**为健康（结构吸收了同形发现）；持续 >1 且不降 = **补丁熵前兆**（缺口产出没有因收敛而下降，即补丁在生新缺口） | 缺口 5 / 动作 0（今天零修复）⇒ 无意义基线，首份周报起计 |
| **won't-fix 数** | 本期判「答不出具体损失」的件数 | **高是好数**（判断在起作用，不是没看见） | 2（`#2` 本域半件 / `#4`；另 1 件判 `already-covered`、1 件根因转上游） |
| **同形收敛数** | 合并成结构件并删除被取代者的件数 | ≥1 / 周 | 0（尚无议程） |
| **删除行数** | `git log --numstat` 区间汇总净行数 | **负数是好数** | 近 12 次提交 +3604 / −20475 ⇒ 净 **−16871**（E 波大扫除） |
| （辅助）**新增零件数 / 修复动作数** | 净零件 ÷ 动作数 | >0.5 = 补丁熵前兆 | — |

> 辅助口径比「发现/动作比」更直接地测「我们是不是在拿新零件换旧问题」，建议与第一行并列展示。

### 8.2 30 秒版式（5 行，推既有通道）

```
① 本周修复 N 件（净零件 +P / 删 −D 行）｜won't-fix M 件｜流血例外 X 件
② 同形收敛 Y 件：<一句话，被取代的是什么>
③ 本期最差一件：<哪件最像补丁，为什么还是修了>
④ 我抽查了两条：<卡 id + 60 秒可核的证据行>
⑤ 提交区间：<from..to>（净 −Z 行）
```

**第 ③ 行是刻意留的**：它逼周报必须包含一件「修了的」并自陈风险，防「永远绿」（人信任漂移的解毒剂）。

- **Q1**：最小事实 = 消费者问的是「有没有货」（观测），`check` 答的是「状态列写了什么」（声明）；实查 `in-flight` 7 件里 7 条零提交空壳（`git rev-list --count origin/main..<branch>` = 0）。
- **Q2**：git = **就是 git 本身**——`git rev-list --count` / `ls-remote` / worktree 干净度是观测态的直接来源，一条命令回答「有没有货」；既有钳夹 = `check` 已存在（改造它是「一段」不是「一行」）；知识层 = skill §3.2 已固化「in-flight ≠ 有货：判 goods 前必查载体现状」。**未覆盖**：`check` 输出未把观测事实打出来（属**优化**，不属修复）。
- **Q3**：能**删**不改？能——不加任何东西，靠既有 skill 口径 + 一条 git 命令（已写在 skill 里）。
- **Q4**：零件 **0**。回退 = 不适用。
- **不修会怎样**：可计量 = 每次判 goods 多一条 `git rev-list`（约 1 秒）+ 可能的 1 次错判（09-13 1 次，已被口径拦下）。兜底 = **有**（skill 口径，09-13 起 0 复发）。
- **verdict: `won't-fix`** → 已知缺陷清单；升级条件 =「再次因空壳被当有货而误判」或「第 2 个同形件出现」⇒ 那时与同形件一起做结构件。

### 9.5 缺口 5 —— 机器行位置（隐藏耦合）

- **Q1**：最小事实 = 钳夹 SQL 只扫 `task_comments`（`join task_comments c on c.task_id=t.id`），而契约没写明行必须落 comment ⇒ 同一约定在两处不同步；根因 = 「约定」没有可执行校验（症状：写 body = 卡永不被唤醒，且**无声**）。
- **Q2**：git（契约在仓内的 skill 里）；看板（钳夹的查询本身即可复用的校验器 = 同一条 SQL）；知识层（skill §4.1 已固化，09-13 起 4/4 卡落对）。**未覆盖**：无。
- **Q3**：能**删**不改？能——不加校验器。能改一行？能（建卡后用钳夹同一 SQL 做一次 dry-run = 一行 sqlite 调用），但见下。
- **Q4**：零件 0（删级）。
- **不修会怎样**：可计量 = 建错位置 ⇒ 该 watch 卡永不唤醒（沉默）；今天暴露 **0 次**（4/4 正确）。兜底 = **有**（每班实读窗口巡检 + skill 契约）。
- **verdict: `already-covered`**。若第 2 次复发 ⇒ 与**缺口 1 合并**成同一个结构件（「同一 SQL 常量供自验与实跑共用」）——两者用的就是同一常量。

## 10. 边界与红线（人门不变，但判据换位）

### 10.1 三条轴（与 v2 一致，v3 不动）

```
轴一 对外动作审批（不变）：L1 全自动 → L2（L2-auto / L2-A / L2-B）→ 链落笔。
     gh 写 / push / PR / 评论 / 发版恒走这里；own-PR 永不进 L2-auto。
轴二 域内机制改动（本设计）：域内可逆 = AI 全权 ｜ 红线 = 人门
轴三 花钱（不变）：预算钳夹 rq.sh budget reserve/refund
```

### 10.2 红线的判据换位（本版对该维的实质修改）

六条红线（不可逆 / 对外 / 凭据 / 删数据 / 调度链 / 宪法层）仍归人，但**判据从「路径」换成「不可逆性」**：

- **判据问句**：「这处改动能不能一行退回去？错了多久能被看见？」→ 能 + 可见 ⇒ 域内可逆 ⇒ AI 全权；不能、或错了不可见 ⇒ 人门。
- **由此的裁定（需用户确认，§13-1）**：`heartbeat.sh` 的**钳夹逻辑**是域内可逆代码（在 git 里、一行可退、错在下一班可见）⇒ 归 AI；**「调度链」红线认的是「何时唤起系统」**——cron job 定义 / launchd plist / 班次编排 / 失败语义的对外承诺 ⇒ 归人。
- v2 §4.4 把「`heartbeat.sh` 的调度与失败语义段」**整段**列入人门 = 路径式残留（它会让缺口 1 永远修不了，而那是净零件为负的宪法一致性修复）⇒ v3 修掉。

### 10.3 域内可逆面（AI 全权）

`martin/scripts/contrib/**`、`martin/docs/**`、`contrib-data/**`（数据面按 `.bak` + 幂等 + 同口径自证）、operator 自己的 skill 正文（口径 / 判例）。红线的**权限条款**（红线清单、类别闸、可做/不可做清单）仍归人——这条不是路径白名单，是「谁定边界」的原则（v1 A1-1 保留）。

### 10.4 风险登记册

见 §3.3（只读 token 不落地；触发条件 = 首次注入痕迹）。
