## 0. 30 秒版

**v2 错在哪（一句话）**：v2 的问法已经对了（「改完谁审、怎么退、谁看得见」），但它把答案落成了**新机制**——只读 token 注入 + 回退点通道 + append-only 哈希链账本。三件都是新的需要维护的东西，而用户判定的根因是**指导不够**，不是机制不够。

**v3 换了落点**：把答案从机制移回指导。

**v3.1 删掉了 v3 残留的最后一道门**：v3 把「修」和「不修」之间插了一道**每周批量议程**（修复集中在每周一次），还为此定义了「流血三判据」当例外。用户 09-13 晚拍板：**这两样一起删**——「只有 2 类。值得修复就马上修复，不值得修就不修，延迟的是什么？」

```
发现缺口 → [fix] 卡上四问（第一性原理 / 已有基建 sweep / KISS 阶梯 / 剃刀）+「不修会怎样」
        ├─ 四问过 + 答得出「不修会怎样」⇒ 当班进修复流（马上修；当天落地，不再等议程）
        ├─ 答不上来「不修会怎样」     ⇒ won't-fix 登记进已知缺陷清单（带 `escalate:` 机器行，条件变化可复活）
        ├─ 本域无解                   ⇒ upstream（轴一：issue-first → L2，本职 KPI）
        └─ 基建/知识层已吸收           ⇒ already-covered，直接关
        → 红队只审「四问答得扎不扎实」（证据链完整性），不审路径白名单
        → 周审只做**事后收敛**（同形合并 / 删除 / 回滚），不做**事前拦截**
```

**机械层归零**（不变）：git 已是回退 + 台账 + 留痕（reflog 实证 amend 可见 + public remote 外部锚），看板已是状态（事件全量表），既有钳夹已是校验（auto-gate / l2_ledger / rq / forge 单写方 / tests + mutation 自证），`.bak` 惯例已是数据面兜底（`contrib-data/` 不在 git）⇒ **v2 的三件套全删**，只读 token 降级为**风险登记册**一条（触发条件=首次注入痕迹）。

**今天 5 个缺口过四问**：修复流 **2 件（当班落地，延迟 0）**、won't-fix **2 件**（另 1 件判 `already-covered`、1 件根因转上游）、人门 **0 次**、**净新增零件 0 个**（`#1` −1 处吞失败形状，`#3` +1 个枚举词，相加为零）。v3（议程门版）同一批的判定完全相同，唯一差别是**落地延迟**（v3 ≤7 天 / v3.1 当班）；实际发生是 **0 行代码改动 + 3 张 [draft] 卡等人 + 每班重复巡检**（附录 D 三方对比）。

**本设计自身零新建机制**——四问 = 卡模板栏目、红队 = 已有先例（板上 6 张 `深检 redteam` 卡 done）、周审 = 宪法 P9 既有 auditor + 既有报告通道、清单 = 看板一张卡、留痕 = git 提交说明。自证表见附录 B。

**诚实的代价（v3.1 版）**：v3 的代价是**修复延迟**；删掉延迟之后，代价换成**没有缓冲**——即修可能修错、修多、修成 N 个补丁。所以 v3.1 的刹车从「时间」换到「**零件计数**」：① 每件必须自证净零件数（Q4），净 >0 要论证「为什么零新增不行」；② 同一 shape 第 2 件出现即**停手转结构件**（当班做，不再攒到周议程）；③ 红队复核 + 周审事后收敛。可反驳承诺：**一个月内出现 ≥2 次「当班修的件被周审回滚或合并掉」，即判即修太毛躁 ⇒ 加一道刹车（新建级改动隔班复核），而不是恢复议程门**（§6.4）。

## 1. 诊断：v2 的两处错位、v3 的一处残留、根因

### 1.1 v2 的两处错位（实证）

| v2 的形态 | 实际后果 | 实证 |
|---|---|---|
| **机械层三件套**（只读 token 物理闸 / 回退点通道 / append-only 决策账 + 哈希链） | 每件都是新的维护面：一本账 + 一个 `verify` 命令 + 一个 token 注入 seam + 周报对锚环节 + 机械抽签 | 用户裁定「太复杂」；且它逆着 AI Native 宪法的终态走（宪法定 `scripts/contrib ≈ 4 文件`、账本 3 本；三件套会变成 6 文件 + 5 账本） |
| **判断发生在事后**（红队七问：真库对拍 / 回退可达 / 爆炸半径…） | 卡上不要求先做「已有基建 sweep」⇒ 缺口一来就进入「修」的默认路径；红队才第一次问「证据扎不扎实」，此时成本已付 | v3 §9 演示：5 个缺口 → 4 件修复（v2 口径），其中 2 件本可被已有基建/知识层吸收 |

### 1.2 v3 的一处残留（v3.1 删掉的东西）

v3 已经把判断成本挪到事前（卡上三行字），但它**在「修」和「不修」之间又插了一道时间门**：修复动作集中在每周批量议程，理由有二——「时间过滤假问题」（登记 ≥7 天没人追债的多半是假问题）+「同形并看逼出结构解法」。

用户 09-13 晚的裁定（原话逻辑）：**「只有 2 类。值得修复就马上修复，不值得修就不修，延迟的是什么？」**

逐条拆开，这道门的两个理由各有更便宜的取代者：

| v3 的门 | 它想解决的 | v3.1 的取代者（更便宜、零新增） |
|---|---|---|
| 时间过滤（等 7 天看会不会被现实追债） | 分清真假问题 | **「不修会怎样」栏**已经要求当场给出可计量损失 + 已有兜底 ⇒ 真假问题当场就能分（今天 5 件里 3 件当场判出已被兜底）；剩下答不出的进清单，清单本身就带 **`escalate:` 机器行**（条件一变化即复活），不需要靠 7 天静置来验伪 |
| 同形并看（攒一周摆一起） | 逼出结构解法而不是 N 个补丁 | **Q3 阶梯 + Q4 净零件计数**逐件就在做同一件事：净 >0 必须论证、同一 shape 第 2 件出现即停手转结构件（§6.2）。并看是**手段**，不是**等待的理由**——当下就有 2 件同形，当下就能并

⇒ **议程门删掉。周审保留，但只剩一件事：事后收敛**（同形合并 / 删除 / 回滚），不做事前拦截。

**「流血三判据」随之整节删除**（v3 §6.3）：那三条判据存在的唯一目的，是给出「什么可以不等议程」的例外清单。议程没了，例外就没有定义域。这不是「放宽」，是**取消了这个维度**（§11 失败模式表里对应删掉「流血滥用」一条，不留空壳）。

### 1.3 根因（用户判断，地基，不变）

**「问题不是修或者不修，而是怎么修复。根因是 AI 的上下文和指导不够——如果 AI 知道 git、被引导优先看已有基建，就可以了。」**

⇒ 缺的是**指导**：把「先看已有基建」变成卡上的**必答栏目**（不写完不进修复流），而不是把「修复」这件事包进新机制。这与 AI Native 宪法 §1 的判据一致——需要「毫不动摇、错了必须拒绝而不是变通」的才进代码层（`contrib-ops-ai-native-design.md:13`）；「怎么修」是判断，归 AI，但判断需要脚手架。

### 1.4 四条实证：为什么「机制化」与「限速」都会反噬

| # | 实证 | 说明 |
|---|---|---|
| a | **v1 的独立决策账 + 哈希链** | 走一遍 Q2（已有基建 sweep）30 秒内被 git 干掉——整件删除。教学案例见 §5 |
| b | **宪法终态**（`contrib-ops-ai-native-design.md:68-81`） | 账本 9 → 3 本、`scripts/contrib` 16+ → ≤4 文件；v2 的三件套方向相反 |

| d | **限速思想的两代残留** | v1 用速率上限挡（A3 ≤2 件/日）⇒ 用户否掉；v3 用时间门挡（周议程 ≤7 天）⇒ 用户 09-13 晚也否掉。两次否掉的是同一个东西：**延迟**。收敛压力应该来自**零件计数**（可当场核），不来自**时钟**（不可加速） |

## 2. 四原则 → 本设计的形态

| # | 原则 | 它问什么 | 落到本设计的形态 | 反过来说（被删掉的形态） |
|---|---|---|---|---|
| 1 | **第一性原理** | 问题的最小事实是什么？修的是根因还是症状？ | **Q1** + 「不修会怎样」（默认动作 = 不修，修需要论证） | 把「发现缺口」直接当「该修」（v1/v2 的隐含默认） |
| 2 | **AI First** | 这个判断能不能交给 AI？ | 判断全归 AI；机械层归零（宪法判据：只有「错了必须拒绝」的才进代码） | v2 三件套 = 把判断写成机制；v1 = 把信任写成许可表 |
| 3 | **KISS** | 能不能不新建？能不能更小？ | **Q2 已有基建 sweep** + **Q3 阶梯**（删 > 配置 > 一行 > 一段 > 新建） | 新建账本 / 校验器 / 哈希基线 / 只读 token 注入 |
| 4 | **剃刀** | 假设最少、零件最少的是哪个？ | **Q4**（最少假设 + 净零件计数）；**同一 shape 第 2 件出现即停手转结构件**（并看是当场做，不是攒到周末） | N 个缺口 = N 个补丁；**也不等于**「攒一周再并看」（v3 的时间门 = 用等待代替收敛压力） |

**设计题眼**：v3 把判断的位置换到成本最低处（事前卡上三行字）；**v3.1 把时间的自由度也删掉**——修与不修的裁决只由「有没有具体损失 + 净零件数」决定，不由「过没过一周」决定。指导的形态是文字，文字的维护成本是零；时间的形态是等待，等待的成本是每班重复巡检（今天 ≥6 处，§9.7 实证）。

## 4. 核心：修复判断四问（`[fix]` 卡模板）

### 4.1 卡模板（可直接粘进 body）

```
标题：[fix] <一句话缺口>          （禁「优化 / 重构 / 加固 / 完善」类无缺口标题）
──────────────────────────────────────────────────────
Q1 第一性原理
   最小事实：<一行代码 / 一条命令级别的事实，无「可能 / 大概」>
   症状→根因链：症状 = <观测> → 层1 = <证据> → 根因 = <最小事实>   （≤3 层）
```

### 4.2 四问的判据（给红队用，每条一句话）

- **Q1 判据**：最小事实能**一条命令复现**吗？「换个写法就好了」= 症状级 ⇒ 打回。今天反面实证：09-13 14:13 首诊「静止态必失败」→ 15:06 修正为「竞态型」，一次单点观测足以把修法带偏（全量换读法 vs 只改参数）。
- **Q2 判据**：**答不出「查过了」= 打回**。逐项点名是为了防自由回忆——「AI 知道 git」不等于「AI 会说 git 已经覆盖了这个需求」。sweep 的目的不是「查了就不修」，是**查了才知道该修多小**，以及**同形已有几件**（决定这件是补丁还是结构件）。
- **Q3 判据**：从上往下走，每级「不行」都要有证据；跨级必须有理由。序：**删 > 配置 > 一行 > 一段 > 新建**。
- **Q4 判据**：零件计数含新增脚本 / 文件 / 字段 / 常量（周流程也算）；删除抵扣；红队拿数字核对。
- **「不修会怎样」栏判据**（v3.1 加严，红队攻击后二次加严）：**只接受可证伪的损失陈述**。「暂无具体损失」不足以直接判 `won't-fix`——必须同时给出①**机器行 `falsify:`**（一条命令 + 一个数字阈值），②**机器行 `escalate:`**（一个可观测触发）。三条硬规则：
  1. **红队有权自选证伪手段**——卡上那条只是起点；红队认为有更强的独立证伪法（更能暴露损失）时，**以红队的为准**，不得被「只许跑卡上那条」限制；
  2. **格式违规直接打回**：`falsify` 写成未来条件句 / 负存在命题（「若再次发生…」「无人拦」「无人发现」）= 缺陷，`REBUT`——这类写法在评审时点**逻辑上不可能产出反例**，等价于自动放行；
  3. **裁决方向**：红队跑完找不到反例 ⇒ `won't-fix` 成立；找到反例 ⇒ `REBUT`。**裁决权在红队，不在填表人**。
- **兜底栏判据**（红队攻击后新加）：兜底的三种形态（巡检 / 契约 / 口径）里，**「口径」最容易自产**——skill 由 operator 全权管理且「写进就生效」（§3.1），所以存在「当班写一条口径 ⇒ 当班宣布损失已被吸收 ⇒ 当班判 won't-fix」的自证闭环。⇒ 两条约束：① 兜底若为口径，必须给出**触发该口径失效的查询**（跑它能看出兜底已经不管用）；② **当班新写的口径不得作为本卡的兜底引用**（引用它 = 自己给自己发免修证）。

### 4.3 四种归宿 + 默认动作（v3.1：无时间门）

| verdict | 去向 | 落地时点 | 记录处 |
|---|---|---|---|
| `fix` | **当班修复流**（§6.2：四问 → 改 → 跑既有验证 → 回退命令跑过一次 → 红队复核 → 提交说明写 why） | **当班**（同一天；跨班只影响 worker 轮次，不构成设计里的延迟） | 卡 + 提交说明 |
| `won't-fix` | **已知缺陷清单**（§6.1）——**必须经红队复核才能登记**（红队是两分法的裁决者，不只是 fix 路的验收者） | 当班登记 | 清单卡一行（登记日 + 缺口 + 「不修会怎样」+ `falsify` + `escalate` + Sunset 日） |
| `upstream` | 轴一（issue-first → L2）——本职 KPI | 当班起草 | 卡 + rq |
| `already-covered` | 直接关（知识层/基建已吸收，不改代码） | 当班 | 卡上写清是哪条口径 / 哪一个基建项 |

**默认动作 = 不修**：无「不修会怎样」论证的缺口不进修复流。
**默认时点 = 现在**：过了四问就是当班修，不再有「等议程」这个状态。**没有任何一件缺口因为「不够流血」而被推迟**——推迟这一维已被删除。

## 5. 教学案例：v1 的独立决策账 + 哈希链，走一遍四问（回测）

> 这件是 v1 §4.3 的核心资产，v2 原样保留并加了哈希链。用四问回测，它在 Q2 就被拦下。

**Q1 最小事实**：我们要回答的是「谁在什么时候改了什么、为什么、怎么退」——最小事实 = 这三问的答案现在存在哪里。

**Q2 已有基建 sweep**（三项命令即可结案）：

| 项 | 命令 | 输出要点 |
|---|---|---|
| git | `git log --numstat` | 改动 + 作者 + 时间 + 提交说明里的理由（实证同 §3.1 表格） |
| git | `git reflog` | `fc46a71 HEAD@{0}: commit (amend)` / `3033c0d HEAD@{1}: commit` ⇒ **amend/重写留痕**（原版本仍在 reflog） |
| git | `git remote -v` | `origin git@github.com:strzhao/martin.git` ⇒ 远端副本 = 外部锚 |
| 看板 | `select … from tasks/task_comments` | 决策情境（为什么这么改）在卡与评论线程里 |
| 知识层 | skill §8 判例库 | 已吸收的规则性条款在这里 |

⇒ **已覆盖 100%，未覆盖：无**。

**Q3 KISS 阶梯**：能删不改？——这件本身就是「新建」（一本 jsonl + 一个 `verify` + 每行 `prev` + 每周对锚）⇒ 三级全否，落到**新建**。

**Q4 剃刀**：假设集合 = {「git 不能提供不可否认性」}——该假设**被排除**（reflog + 远端副本提供同一强度；且篡改者 = AI 自身时，哈希链由 AI 自己写、自己验，边际强度为 0）。零件计数 = 脚本 1 + 文件 1 + 字段 2（`prev`/`review_tier`）+ 周流程 1 = **净 5** ⇒ 必须证明「零新增不行」——它答不了任何问题（唯一边际价值是篡改留痕，已被 git 覆盖）。

**verdict: `already-covered`**（整件删除；只保留一条文字约定：**修复的提交说明必须写 why**）。
**不修会怎样**：损失 = 每周多读一本账、多跑一个 `verify`、多维护一份字段契约（**负收益**，即「不建」才是收益）。
```
falsify: `git log --numstat` / `git reflog` / `git remote -v` 三条命令的输出里，找「三问（谁改了什么 / 为什么 / 怎么退）未被回答」的实例
         阈值：实例数 ≥1 ⇒ REBUT（当前实查 0 条 ⇒ 假设被排除）
escalate: ——（本件判 `already-covered`，不进清单；若日后出现「git 答不了」的具体实例，另立卡）
```

**这个案例的意义**：v1/v2 用 1 本账 + 1 个 append/verify 脚本 + 2 个字段契约 + 1 条周流程建的东西，Q2 三行命令就答完了。v2 保留了它、还加了哈希链；v3/v3.1 删掉它——同一个结论，靠的不是更强的机制，是**「先 sweep 已有基建」这一条指导**。

## 6. 防「多做」三条（v3.1：默认不修 / 当班修 / 周审只收敛）

### 6.1 默认不修：每件先过「不修会怎样」

- **先立卡**（红队攻击后新加的义务）：**当班发现的缺口必须在当班立 `[fix]` 卡**——缺口不得只躺在 `ops-journal` 里。理由：不立卡则四问、红队、清单三闸全部不启动，「闸之前」是最省力的绕过路径（09-13 的实录形态就是「缺口在 journal、3 张 draft 卡等人、0 修复」）。对账由周审跑一条命令（既有件）：journal 里的缺口行 ↔ 看板卡标题/id 的差集，差集 ≥1 即 incident。
- 候选缺口先答「不修会怎样」（具体损失 + 兜底 + `falsify` + `escalate`）；**答不出具体损失 = `won't-fix`**，经**红队复核**后登记进**已知缺陷清单**。
- 清单的家 = **看板上的一张常驻卡**（零新文件、零新脚本；板 = 记忆）：**每个缺口一条评论** = 登记日 + 缺口 + 「不修会怎样」的答案 + `falsify` + `escalate` + **Sunset 日**。
- **清单不是坟场**（防「永不复活」的僵尸条目，三道闸 + 两条形状纪律）：
  1. **入清单必须有 `escalate:` 机器行，且触发必须可观测**——一条命令 / 一个事件能判它是否发生；写成「若再次发生…」这类不可观测的复述，红队 `REBUT`；
  2. **Sunset 到期不得直接删行**（红队攻击后加严）：登记 ≥30 天且未升级 ⇒ 周审**必须附一行证据**（「`escalate` 条件为何已失效」或「损失已消失」的观测）才可标「已自然消亡」删行；**无证据删行 = 形式违规**。删行后同缺口重登必须在评论里标明「重登」——周报数「重登数」（防「删了再登」把清单做成永动循环）；
  3. **容量红线按「缺口数」计，不按评论行数**（红队攻击后加严）：**禁止把多个缺口并成一条评论**（并成「巡检类兜底债务」= 一行装 N 个债）。缺口数 >10 ⇒ 视为**判断在放水**，**后果**（不是提醒）：**本周剩余缺口不得再判 `won't-fix`**，必须逐件落到 `fix` / `upstream` / `already-covered`；并在周报第 ③ 行点名。
- 这一条同时改写了 AI 的**默认行为**：从「发现缺口 = 修」改为「发现缺口 = 立卡 + 论证 + 修或不修」。

### 6.2 当班修复流（过四问即修）

```
四问过（Q1 最小事实 / Q2 已查 / Q3 落到删|配置|一行|一段|新建 / Q4 净零件有数）
  → 改（按 Q3 落点，取最小级）
  → 跑既有验证（tests/run.sh + 相关 mutation 自证 + 真库只读对拍）
  → 回退命令真跑过一次（首次进修复流时；Q4 必答项；**输出贴回卡上**——见附录 E 探测器）
  → 部署面 diff 自证（若落点在 git 之外，§3.1 末行）
  → 红队复核（独立进程 / 独立模型族；`GO` / `GO-WITH-FIXES` / `REBUT`）
  → 提交说明写 why + 卡上落归宿
```

- **不设批量窗口、不设严重度门槛**：没有「流血例外」这个东西——没有延迟，就不需要定义例外。
- **REBUT 的回滚义务**（红队攻击后新加）：当班修 + 跨班红队 ⇒ 存在「改动已 live（部署面 `cp` 后即刻生效）而判词未到」的窗口。⇒ **REBUT 到达时若改动已生效，默认动作 = 立即执行 Q4 登记的那条回退命令**，再谈重做；不许停在「重做或弃」。
- **唯一的刹车是零件计数**：净 >0 必须答「为什么零新增不行」。若答不出 ⇒ 打回 Q3 再降一级（多半能降到「删」或「配置」）。
- **同形刹在第二次**：Q2 的「同形已有几件」答出 ≥1 时，本件的正确落点**默认是结构件**（合并已有 + 删除被取代者），而不是再打一个同形补丁。这是「并看」的落实方式：当场并，不等周末。**「默认」不是「可以论证推翻」的软词**：要推翻必须在卡上写明「为什么这两件不是同形」并接受红队核（否则红队 `REBUT`）。
- 红队可以**跨班**跑（它不占修复者的班），因此「当班修」不会卡在红队排队上；`REBUT` 的处理见 §7.4。

### 6.3 周审：只做事后收敛，不做事前拦截

- **家**：宪法既有的 **P9 每周 fresh-context auditor**（`contrib-ops-ai-native-design.md:26,89`）+ 既有报告通道（cron `69dda6b658de` 开源运营日报 / contrib digest）——**零新角色、零新 cron**。
- **固定四件事（全部是事后动作，没有一件是「批准修复」）**：
  1. **同形合并**：扫本周所有 `fix` 件，把 ≥2 件同形合并成结构件，并**删除被取代者**（产出必须回答「这几件合并成什么、被取代的是哪些」）；
  2. **删除 / 回滚**：扫本周实际改动，指出「最像补丁的那件」与「该回滚的那件」；回滚数与合并数进周报；
  3. **清单体检**：逐条核 `escalate` 触发是否还成立 + 核 Sunset 删行是否**附了证据**（无证据删行 = incident）+ 缺口数容量红线（>10 ⇒ 触发 §6.1 的后果）+ 数「重登数」；
  4. **立卡对账**（红队攻击后新加）：`ops-journal` 里的缺口行 ↔ 看板卡标题/id 的差集——差集 ≥1 即 incident（防「缺口只躺在 journal、四问根本没启动」；这是唯一能探测「漏登记」的机械口，因为被降级为观察的「发现/动作比」不再承担这个职责）。
- **抽检（第 ④ 行）的责任人只有一个版本**（红队指出 v3 写得四处互相指，此处统一）：**周审（P9 auditor，AI）出机械抽样候选**（口径：本周**最后一张** `[redteam]` 卡 + 本周**唯一的**回滚件，不由写周报者挑「好看的那条」），**人核其中一条**（<60 秒）。
- **周审不改判、不追批**：它不审「这件该不该修」（那是四问 + 红队的事），只审「修完之后是不是收敛的」。**没有任何一件缺口因为周审而等待**——周审的输入是已经落地的改动，不是待办。

### 6.4 诚实的代价（可反驳承诺，v3.1 版）

- v3 的代价是**延迟**（议程 ≤7 天）。v3.1 删掉延迟，代价变成**没有缓冲**：即修可能修错、修多、修成 N 个补丁。v3.1 自陈这个风险，并把刹车从时间换到零件计数（§6.2）。
- **可反驳承诺**：**一个月内出现 ≥2 次「当班修的件随后被周审回滚或被合并掉」⇒ 判即修太毛躁 ⇒ 加一道刹车（新建级改动隔班复核）**。注意刹车**不是恢复议程门**：延迟只对「新建」级恢复，且是「隔班」（数小时）不是「隔周」。
- 今天 5 个缺口的实测支持「当班修」：2 件判 `fix`，落点分别是「删 1 处 + 改 1 参数 + 换 1 表达式」（净 −1）与「加 2 词 + 收编 1 条漂移」（净 +1）——**两件的回退命令都是一条命令**，即修错也在下一班可见、一分钟可退。**当班修的风险面 = 回退成本**，而这两件的回退成本恰好是最低档。

## 7. 红队：审「四问答得扎不扎实」，不审路径白名单

### 7.1 三条硬纪律保留（结构性 fresh context 的充分条件）

1. **换进程**：独立 agent 进程/会话（不是同 context 自我复核）。
2. **只给产物**：输入 = 卡 + 产物 + 证据 + 原则；**不给**修复者的论证叙事。
3. **换模型族**：红队卡固定与修复方不同的 `provider`。

先例是**已在跑**的形态，不是纸面：板上 `深检 redteam` 卡 6 张 done（`t_9806a0b2` / `t_eb5a8969` / `t_e3e4fef4` / `t_7a59ef39` / `t_e06cbc66` / `t_b8043d17`）；结构性 fresh-context 的机制锚 `hermes-contribution.md:227`（「两次独立 `claude -p` 进程 = 结构性 fresh-context」）。**注**：v2 引用的 `.claude/skills/contrib-watch/SKILL.md:119` 已随 E 波退役（目录已不存在），本版沿用 v3 更正后的活锚。

**三条纪律的机械落点（红队指出「由被审方自执」后新加）**：红队卡 body 必写 **`fixer_provider:` / `redteam_provider:`** 两个机器行（可与 config 逐字核对，判「换模型族」是否成立）；红队 prompt **由模板生成**（模板里不含论证叙事，杜绝「顺手附上理由」）——但「红队不得由被审者本人起」这一条在**单 operator 域内无法机械核实**（修复者与复核者都是 AI、同一进程族）⇒ **明写为局限**，对冲只剩周审的机械抽样人核（§6.3）。

**v3.1 的强度声明（诚实，红队攻击后补全）**：四问是文字指导，它自身的强度上限 = **复核者的对抗强度**。红队是本设计的**单点依赖**——红队退化成套话，四问就退化。此局限不假装已解决，只做四件事减弱它：换模型族 + 独立进程 + 周审机械抽样人核（§6.3）+ 附录 E 的「文字义务 → 探测器」映射表。

**残余约束清单（红队要求明写）**：红队死亡时，**本设计对「判断质量」的机械约束 = 0**。残余约束 **100% 继承自既有件**——`auto-gate`（own-PR 永不 auto）、`l2_ledger`（approved.log 唯一写者）、`rq`（配额）、`forge`（单写入口）、`tests/run.sh` + mutation 自证、真库只读对拍、`git reflog` + public remote、`.bak`、部署面 `diff`。**这些件只约束「改完之后对不对 / 退得回去吗 / 对外动作合不合规」，对「该不该修、修多小、什么算『不修会怎样』」零约束**——而后者恰是 v3.1 的核心判断维度。这句话是本设计对自己效力边界的最终陈述。

### 7.2 审法（逐问；红队必须**拿命令重跑**，不接受转述）

| 问 | 红队要做的 |
|---|---|
| Q1 | 最小事实能否一条命令复现？对照实验是**同刻**的吗？（单点观测会把修法带偏——今天 14:13→15:06 的实证） |
| Q2 | **重跑** sweep 的每条命令，逐项核对「已覆盖 / 未覆盖」；发现漏项（尤其漏掉「git 已覆盖」）= `REBUT`；核对「同形已有几件」是否真查过 |
| Q3 | 每级「为什么不行」是否有证据；有没有跨级（能删的去改一行、能一行的去新建） |
| Q4 | 零件计数是否漏计（新增常量 / 字段 / 周流程都算）；净 >0 时「为什么零新增不行」是否成立；回退命令是否真跑过（**要求：演练输出贴回卡上**，不接受「跑过吗：是」这个自报布尔）；落点在 git 之外时部署面 `diff` 是否做过 |
| **红线分类**（红队攻击后新加） | §10.2 的红线判据是「能不能一行退回去？错了多久能被看见？」——**由被赋权方自判**，而原审法表不含此项。⇒ 红队必须独立核一遍：这处改动**能不能一行退回**（回退命令实跑）、**错了多久可见**（下一个观测点是什么）；两项答不出 ⇒ 该件不进修复流，转人门 |
| 不修会怎样 | **本栏是红队的重点战场**：可计量损失有没有数；兜底是否真的盖得住（兜底=口径时，**跑那条「触发失效的查询」**，且口径不得是本卡当班新写的）；`falsify:` **机器行在不在**、格式合不合规（未来条件句 / 负存在命题 = 直接判缺陷）、**能不能真的证伪**（红队有权换更强的独立证伪法，找不到反例才放行）；`escalate:` 触发是不是可观测的。**won't-fix 未经本栏复核不得登记**（§4.3） |

### 7.3 红队**不审**什么

路径白名单、diff 行数上限、参数方向表——这三样是 v1/v2 的许可表面，v3 已删。红队审它们 = 把判断换回枚举（正是用户否掉 v1 的理由）。

### 7.4 红队自己也要过 KISS

红队卡 = 既有 kanban 卡（`[redteam]`）+ 独立 `claude -p` 进程，**零新建 profile、零新建 lane**。判词三态保留：`GO` / `GO-WITH-FIXES`（列必修项）/ `REBUT`（含理由）。

**判词的归宿（红队攻击后重写——原稿「重做或弃」是漏洞）**：

- **禁止无记录「弃」**：`REBUT` 不得以「弃」结束。**REBUT 必须落到四种归宿之一并写回卡**（`fix` 改判重做 / `won't-fix` 强制登记 / `upstream` / `already-covered`），并在卡评论里留下判词原文 + 处置一行。理由：原稿的「弃」会让一个**已被红队确认存在的损失**从账面上完全消失（不修、不登记、不进任何指标）。
- **REBUT 的回滚义务**：若改动已生效（部署面 `cp` 已发生 / cron 已 pick up），到达即执行 Q4 登记的那条回退命令（§6.2）。
- **`GO-WITH-FIXES` 的必修项必须逐项核销**才能把卡推到终态（否则它只是一个软 `GO`）。
- **判词与处置都留在卡评论里**（可 grep）⇒ 周审机械抽样（§6.3）+ 周报「REBUT 数」（§8.1）都有取数口；`REBUT` 本身仍不上报给人（不上微信），但**留痕**。

## 8. 周报健康指标（人读 30 秒）

### 8.1 四个数（+ 三个辅助口径）

| 指标 | 口径 | 健康方向 | 基线（09-13 实查） |
|---|---|---|---|
| **发现/动作比** ⚠ | 本周新登记缺口数 ÷ 本周修复动作数 | 走低为健康（结构吸收了同形发现）；持续 >1 且不降 = **补丁熵前兆** | 缺口 5 / 动作 0（今天零修复）⇒ 无意义基线，首份周报起计 |
| **won't-fix 数** ⚠ | 本期判「答不出具体损失」的件数 | 「高是好数」**只在清单存量同时下降时成立**；若 won't-fix 数高而存量不降 = **放水信号**（红队指出原稿这里是唯一奖励橡皮图章的指标） | 2（`#2` 本域半件 / `#4`；另 1 件判 `already-covered`、1 件根因转上游） |
| **同形收敛数** | 合并成结构件并删除被取代者的件数 | ≥1 / 周 | 0（尚无周审） |
| **删除行数** | `git log --numstat` 区间汇总净行数 | **负数是好数** | 近 12 次提交 +3604 / −20475 ⇒ 净 **−16871**（E 波大扫除） |
| （辅助）**新增零件数 / 修复动作数** ⚠ | 净零件 ÷ 动作数 | >0.5 = 补丁熵前兆 | — |
| （辅助）**清单存量 C 行（Δ 本周期）+ 重登数** | 清单卡的缺口条目数；本周期净增/净减；因 Sunset 删后重登的条数 | 存量不降 = 放水；重登数 >0 即需逐个说明 | 0（清单卡尚未建立） |
| （辅助）**REBUT 数 / 被推翻的 falsify 率** | 本周红队判 `REBUT` 的件数 ÷ 本周受审件数；`falsify` 被判格式违规的条数 | **>0 是好数**（红队在真干活）；长期恒 0 且清单在长 = 红队已退化 | — |

> ⚠ **三处标注**：
> 1. **用户 09-13 晚要求**：**「发现/动作比」与「新增零件数/动作数」可能被博弈**——分子（登记几件）与分母（修几件）都由 AI 自己填、自己执行，模型完全可以靠「少登记」或「多凑修」把比值做漂亮。⇒ 这两个数**保留但仅作观察，不驱动任何动作**。
> 2. **红队补标**：**「won't-fix 数」与上面两个数同级可博弈**（判断者是同一方），因此它的健康读法挂钩**存量**（存量降才算好）。红队原话结论：橡皮图章的唯一产物恰好是「高 won't-fix 数」，而原稿把它写成健康方向 —— 这是指标图例反了。
> 3. **真正驱动判断的数**：**删除行数**、**同形收敛数**、**清单存量 Δ**、**REBUT 数**——它们指向具体提交 / 具体被删件 / 具体判词，人可一分钟抽查。**「发现/动作比」被降级为观察后，「漏登记」这个向量必须由一条新探测器补上**（周审的 journal ↔ 看板对账，§6.3 第 4 件）——否则就是「承认博弈向量之后弄瞎唯一的探测器」。

### 8.2 30 秒版式（5 行，推既有通道）

```
① 本周修复 N 件（净零件 +P / 删 −D 行）｜won't-fix M 件｜回滚 R 件｜清单存量 C 条（Δc）
② 同形收敛 Y 件：<一句话，被取代的是什么>
③ 本期最差一件：<哪件最像补丁，为什么还是修了>（含本周唯一的回滚件）
④ 我抽查了两条：<卡 id + 60 秒可核的证据行>（本周最后一张 [redteam] 卡的判词 + 其中一条回退演练输出）
⑤ 提交区间：<from..to>（净 −Z 行）｜REBUT K 件（含处置）
```

**第 ③ 行是刻意留的**：它逼周报必须包含一件「修了的」并自陈风险，防「永远绿」（人信任漂移的解毒剂）。
**第 ④ 行**：抽检候选由**周审机械抽样**给出（不由写周报者挑），一条抽红队判词、一条抽回退演练的**输出**（不是「跑过吗：是」这个自报布尔——红队指出该布尔原本没有任何锚可查）；人核一次即可。**第 ⑤ 行的 REBUT 数**是红队是否在干活的唯一直接读法（红队退化 ⇒ 恒 0）。

### 10.2 红线的判据（v3 已换位，v3.1 沿用）

六条红线（不可逆 / 对外 / 凭据 / 删数据 / 调度链 / 宪法层）仍归人，但**判据从「路径」换成「不可逆性」**：

- **判据问句**：「这处改动能不能一行退回去？错了多久能被看见？」→ 能 + 可见 ⇒ 域内可逆 ⇒ AI 全权（且 v3.1 下 = 当班做）；不能、或错了不可见 ⇒ 人门。
- **裁定（需用户确认，§13-1）**：`heartbeat.sh` 的**钳夹逻辑**是域内可逆代码（在 git 里、一行可退、错在下一班可见。注意部署面 = 手工 `cp`，所以修复流固定带 `diff` 自证）⇒ 归 AI；**「调度链」红线认的是「何时唤起系统」**——cron job 定义 / launchd plist / 班次编排 / 失败语义的对外承诺 ⇒ 归人。
- v2 §4.4 把「`heartbeat.sh` 的调度与失败语义段」**整段**列入人门 = 路径式残留（它会让缺口 1 永远修不了，而那是净零件为负的宪法一致性修复）。

### 10.3 域内可逆面（AI 全权）

`martin/scripts/contrib/**`、`martin/docs/**`、`contrib-data/**`（数据面按 `.bak` + 幂等 + 同口径自证）、operator 自己的 skill 正文（口径 / 判例）。红线**权限条款**（红线清单、类别闸、可做/不可做清单）仍归人——这条不是路径白名单，是「谁定边界」的原则（v1 A1-1 保留）。

**v3.1 补一句**：落点在 git 之外的部署面（`~/.hermes/scripts/**` 等）**属于域内可逆**，但必须满足两条——① 仓内有真源且逐字节一致（`diff` 自证）；② 回退 = `git revert` + `cp` + `diff`，且这道回退命令**跑过一次**。不满足这两条 ⇒ 归人门。

| 8 | **人信任漂移** | 周报永远绿 → 人不读了 | 周报第 ③ 行（本期最差一件）+ 人核两条（<60 秒，含一条红队判词）；人核出问题即 incident |

## 附录 E — 文字义务 → 探测器映射表（红队攻击 ⑧ 的答卷）
