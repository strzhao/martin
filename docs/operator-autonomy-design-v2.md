## 0. 30 秒版

**v1 错在哪（一句话）**：它回答的是「AI 不许改什么」，于是把信任写成了**许可表**——参数方向表、路径白名单、六道闸、80 行上限、变更预算。许可表有两个死穴：①永远列不全（每个新脚本路径都要回改白名单，白名单才是最大的补丁生成器）；②它把 AI 的目标从「把管道弄健康」偷换成「别越线」。

**v2 换了问题**：不问「AI 能改什么」，问 **「AI 改完，谁审、怎么退回、谁看得见」**。

```
发现 → 诊断 → 修复 → 红队复核 → 真库自证 → 上线（恒留回退点） → 守候 → 每周 AI 审计
  ↑        全流程 AI 闭环，人不出现在这条链上        ↑
  └──── 唯一的人门：不可逆/对外/凭据/删数据/调度链/宪法（六条红线原则）────┘
```

**机械层只剩三件**（其余全是 AI 判断）：① 不可逆红线的**物理闸**（只读 token，让 gh 写在服务端 403）② **回退能力**（apply 恒留一行可退的回退点）③ 决策账的 **append-only 强制**（哈希链）。
**人只剩四件事**：拍红线原则、读一页周报、异常介入、持凭据。**日常修复不再过人的手。**

**今天的 5 个缺口**在 v2 下的动作数：域内自修 4 件（含 2 件结构性收敛）+ 转上游 1 件（kernel 停放语义，走本职 L2 路），**人门 0 次**；机械层新增文件 0 个（只多一本账）。v1 下同一批的动作数是「2 补丁 + 1 次人工拍板 + 2 次零动作」，且要同步改白名单 3 次、新写 6 道闸脚本。

**残余风险我写在纸面上**（§9）：AI 审 AI 有同谋盲区与能力同源两处真实失效模式，反制是「红队只拿产物不拿论证 + 跨模型族 + 真库对拍（唯一与模型无关的证据）+ 人按机械抽签抽查」，且我不宣称它万能。

## 1. AI First 原则（本设计的宪法）

### 1.1 用户既有原则（09-11 拍板，凌驾本文件其余条款）

- **减少对人依赖**：escalate 只剩三种正当理由——①不可逆 ②预算资源类 ③缺判断依据；取舍类按已有原则自决。
- **禁维护规则清单限制 AI**：拿不准选更保守的**可逆**项；自决留痕 `自决:<原则名>`，决策清单供回溯。
- **机制优化自留拍板，但日常运转的判断全部放给 AI**。

**本设计对第三条的裁定**（这是 v1/v2 的唯一命名性分歧，需用户确认）：「机制优化自留拍板」拍的是**边界**——红线原则、授权范围、三件机械层自身的改动权；不是**边界的实现**——域内可逆的脚本/配置/数据/知识改动全归 AI。否则第三条与该原则的第一条自相矛盾（日常运转的最大一类判断就是「机制坏了怎么办」）。

### 1.2 v1 为什么是反的（诊断 + 实证）

| v1 的形态 | 它的实际后果 | 实证 |
|---|---|---|
| 路径白名单（可改哪些文件） | 每加一个脚本要回改白名单；白名单成为补丁的主要来源 | 今天 5 个缺口涉 3 个不同文件域，按 v1 要改白名单 3 次 |
| 参数方向表（只能调保守） | 把「该不该放松」写成表格，表格永远缺行；且放松=预算类本就该走人门，无需第二套表 | v1 §7-3 自己承认「某些合理放松也要问人」 |
| 六道闸 | 闸的是**产物形状**（≤80 行/≤3 文件），而 v1 自己识别的头号风险是**语义错误**——产物形状测不出语义 | v1 §5.4 自陈「测试绿 ≠ 语义对」 |
| 变更速率上限（≤2 件/日） | 限额挡住的是真需求，熵的真正对手是**收敛**不是减速 | v1 §4.1 自陈「正确动作数远小于缺口数」 |
| 决策账 / 三次法则 / Sunset | **这三条是对的**（本设计原样保留并换执行者） | v1 §4.2–4.4 |

**一句话**：v1 的每一条规则都在防「AI 变坏」，没有一条在帮「AI 变好」。而防变坏的代价是把维护负担搬进了最不该长的层（机械层）——这正是 v1 声称要防的补丁熵，换到了元层。

### 1.3 六条设计原则（→ 本文件的形态）

| # | 原则 | 落到本设计的形态 | 反过来说（v1 的形态） |
|---|---|---|---|
| P1 | **AI 是修复主体，不是被闸的对象** | 域内可逆的修复：自己诊断、自己修、自己验、自己上线（§3） | 立项 → 车道 → 六道闸 → 人点一次 |
| P2 | **用 AI 审 AI 代替规则清单** | 每件修复过 fresh-context 红队复核（§5） | 路径白名单 + 80 行上限 |
| P3 | **治理靠原则 + 判例，不靠规则** | 宪法给红线原则；判例库随运行沉淀；每次决策引用原则+判例并留痕（§6.1） | 枚举「能/不能」 |
| P4 | **信任但全量可回溯** | 所有改动落决策账；auditor 也是 AI，每周 fresh context 审全部账 + diff，出人读周报（§6） | 人逐条批，或靠 prompt 自律 |
| P5 | **晋级凭证据，出事自动降** | shadow→auto 凭运行证据；回退机制常备；不可回退事故自动冻结（§7） | 人拍级别，靠人盯 |
| P6 | **少机制、多智能** | 机械层只留三件（§4）；凡能用 AI 判的绝不用规则 | 六道闸 + 两张表 + 哈希基线 |

**设计题眼**：AI First 不是「少约束」，是**约束换了位置**——从事前的允许表，换到事后的可见性 + 可逆性 + 一道真物理门。

## 3. 架构：修复闭环（全流程 AI 角色分工）

### 3.1 一条链（没有人的节点）

```
[发现] operator 班内实查：症状（日志/账本不符/静默失效/重复人工绕行）
   ↓ 物化 [fix] 卡（缺口/证据锚/最小修法/回退法/证据契约）
[诊断+修复] fixer specialist（fresh context；代码走 coder lane §⑨ 配方；纯数据/知识类 operator 自做）
   ↓ 产物：分支 + diff + mutation 自证 + 真库对拍 + 失败语义声明
[红队复核] 红队 specialist 卡（fresh context + 跨模型族）→ GO / GO-WITH-FIXES / REBUT
   ↓ REBUT → 回 fixer 重做或弃（不上报给人）
[上线] write 落地：恒留回退点 → apply → 决策账一行（append-only）
   ↓
[守候] 观察窗（默认 2 班，AI 按爆炸半径自定并写理由）→ 症状是否复发 / 新⚠
   ↓
[周审] weekly AI auditor（fresh context + 跨模型族）→ 人读周报 + 收敛动作 + 抽查锚
```

### 3.2 角色表（谁、什么 context、可写什么）

| 角色 | context | 可写 | 不可写 |
|---|---|---|---|
| **operator**（班卡） | 全局视野，重上下文的**判断** | 看板、journal、决策账（经 append helper）、知识层 | 无 —— 域内可逆动作全权 |
| **fixer**（`[fix]` 卡） | fresh，单缺口 | 分支/文件（经回退点机制）、卡、证据文件 | 红线面（§4.4 六原则） |
| **红队**（`[redteam]` 卡） | **结构性 fresh**（独立进程，且**只拿产物+证据+原则，不拿修复者的论证叙事**） | 只读 + 自己的判词 | 任何产物本体 |
| **auditor**（周卡） | fresh + 跨模型族 | 周报、收敛/删除动作卡、incident 记录 | 被审计对象的原文件（发现即开卡，不代改） |
| **人** | — | 红线原则、凭据、周报阅读、异常介入 | 日常修复（不再出现在 §3.1 链上） |

**为什么红队不给论证**：给论证 = 让它审「论证自洽吗」；只给产物 = 逼它自己从产物重建推理，重建不动的地方就是缺陷暴露点。这是我们自己在深检里已验证的形态（`contrib-watch/SKILL.md:119`：两阶段由两个独立 `claude -p` 进程执行、中间只靠文件版次传递）。

### 3.3 与既有轴的关系（三轴正交，别读混）

```
轴一 对外动作审批（不变）：L1 全自动 → L2（L2-auto / L2-A 微信 / L2-B 会话）→ 链落笔
     ↑ 任何 v2 赋权都不豁免它。gh 写 / push / PR / 评论 / 发版恒走这里；own-PR 永不进 L2-auto。
轴二 域内机制改动（本设计）：AI 全权（域内可逆）｜ 人门（六条红线原则）
轴三 花钱（不变）：预算钳夹 rq.sh budget reserve/refund
```

v2 对轴一**只加固不改动**：机械层第①件（只读 token）把轴一的地基从 prompt 级提到服务端级（§4.1）。

### 3.4 卡的形态（新增三种，不新增 profile）

| 卡 | 本体 | 依赖 |
|---|---|---|
| `[fix]` | 一个缺口 + 证据锚 + 最小修法 + 回退法 + 证据契约 | 无 |
| `[redteam]` | 一件待复核产物（只给产物与原则） | `parents=[fix 卡]`（fixer 完成后自动派） |
| `[audit]` | 周审（读全账 + 全 diff，出周报与收敛卡） | 无（定时） |

拓扑用既有 `kanban swarm`（`hermes_cli/kanban_swarm.py:106-127` 已有 verifier/synthesizer 角色先例）或 `parents=[...]` 串联；**跨模型族由 `kanban_create(model=…, provider=…)` 卡级固定**（工具面已支持，配置里现成三个异构 provider：deepseek-flash / glm-flash / kimi-coding k3）。

## 4. 机械层三件套（本项目里仅有的硬约束）

> 判据（沿用 AI Native 宪法）：需要**毫不动摇、错了必须拒绝而不是变通**的 → 机械层。算得出一句话能说清「它为什么必须是代码」的，只剩三件。

### 4.1 ① 不可逆红线的物理闸：凭据分离（"scope the token, not the trust"）

**现状（实查，2026-09-13）**：`gh auth status` → `Logged in to github.com account strzhao (keyring)`，token 前缀 `gho_`，scopes `repo / workflow / gist / read:org / admin:public_key`；contrib profile `toolsets: [hermes-cli, kanban]`（terminal 可用）。⇒ **contrib worker 今天物理上就能 `gh pr comment` / `gh pr merge` / `git push`**。v1 说的「只读只是 prompt 级」不是推测，是本节这段输出。

**机械层做法**：
1. **只读 PAT 注入 worker 环境**（`GH_TOKEN`，`gh` 的凭据优先级：`GH_TOKEN` > 存储凭据）。只读 PAT 在 GitHub 侧就是 `contents:read / issues:read / pull_requests:read`，写请求由**服务端**返回 403——不是「不许调」，是**调了没用**。
2. **可写凭据只存在于轴一的执行体**：`scripts/approval/execute.sh` 由 launchd/cron 独立调起、走自己的 env seam，写 token 不进 worker 环境。
3. **审计兜底**：worker 环境里的任何写企图在服务端 403 → 每周扫描 403/写动词命中，**入周报（越权企图是资产，不是噪音）**；auditor 每周核对 worker 侧 scopes 仍是只读。
4. **兜底第二层（可选、零成本）**：`approvals.deny` glob（既有硬地板，实查 `tools/approval_floors.py:23-56`：命中后连 `--yolo` / `mode=off` 也拦，拒绝语明写 "It cannot be executed via the agent — not even with --yolo"）。它能拦命令级形态，但拦不住「换个工具绕」，所以是**兜底不是主闸**。

**诚实声明**：凭据分离不是「绝对不可能」——同一 OS 用户仍能读 env seam 文件。它把越权从**无声的日常可能**变成**一次可见的密钥读取 + 服务端 403**。机械层的价值是**让红线物理中介化且可见**，不是形而上学地不可能。这一点必须写明白，否则设计就在骗自己。

**失败语义（fail-loud）**：token 未注入/失效 → `gh` 退化为匿名只读（公共数据可读、私有仓 401）⇒ **所有上游实查降级但绝不误报成功**；班内检测到即 journal 记 ⚠ + 周报红行。

### 4.2 ② 回退能力：apply 恒留一行可退（"先自动化回退，再自动化修复"）

- 域内一切 write 经**统一 apply 通道**：git 仓内 = 分支 + `before_sha`；非 git 文件/账本数据 = `.bak-<ts>` + 原子写（本域已有实证做法，journal 09-13 13:12）。
- apply 通道**必须同时产出**：回退命令（`git revert <sha>` 或 `cp .bak-<ts> <file>`）、决策账一行、观察窗到期时刻。
- **回退点缺失/账本写入失败 → apply 拒绝（fail-closed）**。这里允许 fail-closed（与上游 hermes「偏好 fail-open」的判例不冲突）：本地拒绝不损坏数据、也不需要重试变通，只是把决定推回红队/人。
- **首次 auto apply 之前，必须真跑一次回滚**（机械可执行，不是口头承诺；v1 §6 P3 的验收条件原样保留）。

### 4.3 ③ 决策账 append-only（哈希链 + 外部锚）

- `contrib-data/decision-ledger.jsonl`，唯一写入口 = `contrib-ledger append`（`O_APPEND` 打开，不提供改写/截断路径）；每行含 `prev` = 上一行 sha256 → 断链/删行/重排**可机械检出**（`contrib-ledger verify`，rc≠0 即 incident）。
- **外部锚**：周报头部带「账本条数 + 头哈希」。人手里的微信记录是不可被 AI 改写的副本 ⇒ 即使 AI 重写账本与链，下一周周报会与上周锚不符。**零新机制**（周报本来就要发），这是本设计里最便宜的一条不可否认性。
- 记什么：**一切改变管道行为或自身约定的动作**（修复 / 配置 / 数据恢复 / 知识层的规则性条款 / 协议变更）+ 红队判词。纯观察（A0）仍走 `ops-journal` 四行，不进账本（防账本通胀）。

### 4.4 为什么只有三件（其余一律归 AI 判断）

| 不放进机械层的典型 | 理由 |
|---|---|
| 「哪些路径可改」 | 清单列不全；路径不决定风险，**语义**决定风险 |
| 「diff 多大算大」 | 80 行上限挡不住 20 行的错语义，只挡住 100 行的对修复 |
| 「配额/速率」 | 限额挡真需求；熵的对手是收敛（§6.4） |
| 「哈希基线保护闸门文件」 | 它保护的是许可表；许可表没了，要保护的是审计根（§6.3） |
| 「参数能往哪调」 | 放松=预算类（宪法已定的人门），收紧无需授权 |

**六条红线原则**（人门的全部判据，来自宪法，非本设计新造）：**不可逆 / 对外 / 凭据 / 删数据 / 调度链 / 宪法层**。凡被触及 → 人。特别注意两条推论：
- **改对外动作的执行体**（`scripts/approval/**`）等于改红线本体（它的职责就是守不可逆）⇒ 人门。这条是原则推论，不是路径白名单。
- **调度链**（cron/launchd 定义、`heartbeat.sh` 的调度与失败语义段、hermes 本机框架）⇒ 人门；但**上游 hermes 仓**的修复是本职 KPI，走轴一（issue-first → L2），不被人门挡住（§8.2 演示）。

## 5. 红队复核协议（AI 审 AI）

### 5.1 三条硬纪律（结构性 fresh context 的充分条件）

1. **换进程**：红队必须跑在独立的 agent 进程/会话里（不是同一 context 里的自我复核）。
2. **只给产物**：输入 = 产物（diff/文件）+ 证据（mutation/对拍输出）+ 相关原则；**不给**修复者的推理叙事、不给「我为什么这么改」。
3. **换模型族**：红队卡固定 `provider` 与修复方不同（现成：deepseek-flash / glm-flash / kimi-coding）。

### 5.2 红队七问（**这是复核者的思考清单，不是许可表**）

1. 修的是**根因**还是症状？（改成「下次还会不会以另一种形状复发」）
2. **语义**对不对？（不只测试绿：把判据换成真实输入，行为是否仍正确）
3. **真库对拍**证据成立吗？（同一份真实数据上旧/新逻辑的输出差异是否可见；证据是否是空心断言）
4. **爆炸半径**：谁被影响、影响多久、错多久能被发现？
5. **回退**真的可一行执行吗？（红队要实际核回退命令可达，不是读一遍）
6. 与既有**判例/原则**冲突吗？（引用 skill §8 判例逐条对照）
7. **反身性**：这次改动是否在给自己扩权（触及授权/审计/门禁/凭据/调度/知识层的规则性条款）？命中 ⇒ 判词必须显式标注，并在周报里置顶给人看。

红队输出三态：`GO` / `GO-WITH-FIXES`（列必修项）/ `REBUT`（含理由）。**REBUT 不上报给人**，回 fixer 重做或弃——这是「减少对人依赖」的直接体现。

### 5.3 复核深度由 AI 现场判（把「分档表」换成「可辩护的判断」）

不做「评论类免红队 / 代码类必红队」的分档表（那就是许可表换个名字）。改为：**fixer 在 `[fix]` 卡里写 `review_tier` + `review_reason`**（引 P1「可逆性 × 爆炸半径」），红队与 operator 可上调不可下调；**auditor 事后检查档位是否可辩护，系统性低估 = incident**。这就是 AI First 的做法——判断替代枚举，但判断必须留痕、可被事后反驳。

### 5.4 红队自己的失败模式与反制

| 模式 | 机理 | 反制 |
|---|---|---|
| **点头机器** | 长期 GO 率 100%，复核退化为仪式 | 审计统计 GO/REBUT 分布；「零 REBUT 的连续周数」是 auditor 的固定质询项（不是硬阈值，是必须解释的信号） |
| **同谋盲区** | 与修复者共享同一错误框架 | 只给产物不给论证（5.1-2）；七问第 1/7 问强制换框；真库对拍（唯一与模型无关的证据） |
| **能力同源** | 不同模型共享训练语料与先验 | 跨模型族（降相关，不保证解相关）；**人机械抽签抽查**（§6.3）；真实世界的独立信号（症状是否复发） |
| **越权** | 红队自己动手改产物 | 红队卡只读；产物本体只有 apply 通道能写 |

### 5.5 为什么我敢押「AI 审 AI」（战绩，不是我方自夸）

本域已在跑同构形态，且有「红队抓到真缺陷」的账：

| 场景 | 红队抓到了什么 | 锚 |
|---|---|---|
| #101136 review 首战 | **推翻** misfire 断言，反转出 manual-run 双向缺口（in-gateway 借 runner.adapters 无门控 / CLI 死 token） | `contrib-data/ledger.md:13` |
| #83993 deferred 收据 | 4 必修（含 `finish_execution` 是 emit 非持久化的事实反转）+ 4 建议全吸收 | `ledger.md:9` |
| issue#103271 build | 揪出 `or True` 掩盖的**空心断言**（修后同时钉住 green→passed / edit→stale 两转移） | `contrib-data/runs/2026-09-05-issue103271/BRANCH.md:5` |
| rq-20260906-104176 | 红队**拒绝越权**：把形态裁决退回 strategist，不自行改判 | `runs/deep-check/rq-20260906-104176/redteam.md:7` |

最后一条尤其重要：红队既有抓缺陷的能力，也有**不越权**的纪律先例。

## 6. 决策账与 AI auditor

### 6.1 账行契约（append-only jsonl）

```json
{"ts":"2026-09-13T16:02:11+08:00","id":"fix-20260913-01","class":"fix|config|data|knowledge|protocol",
 "target":["scripts/contrib/heartbeat.sh"],"shape":"silent-failure-swallow",
 "why":"到期钳夹读取在 WAL 静止态静默失败（journal 09-13 14:13；15:06 修正为竞态型）",
 "decision_reason":{"principle":"P1 可逆性×爆炸半径","precedent":"skill §8 判例 2026-09-13","self_decided":"自决:失败必须显式"},
 "review_tier":"full","review_reason":"静默失败类，错 48h 才可见",
 "redteam":{"verdict":"GO-WITH-FIXES","model":"glm-5.3-flash","entry":"t_xxx#c12"},
 "evidence":{"mutation":"RED→GREEN 已复现","recon":"同一 board 库旧/新读法 rc 对照 4/4"},
 "before_sha":"…","after_sha":"…","rollback":"git revert <sha>（已核可达）",
 "observe_until":"2026-09-13T18:00+08:00","review_by":"2026-12-12","prev":"<上一行 sha256>"}
```

- **未落账的动作视为违规**：auditor 比对文件 mtime / git log 与账本，缺一即 incident。
- `self_decided` 承载宪法要求的「自决:」前缀（取舍类自决必须写在这里，而不是散在散文里）。

### 6.2 auditor 的职责（AI，每周一次，fresh context + 跨模型族）

**它不是报表生成器，是反驳者**。设备审 `[audit]` 卡，输入 = 本周全账 + 全 diff + journal + 红队判词 + 403/写企图 + scheduled 列状态 + 症状复发率。固定议程：

1. `contrib-ledger verify`（哈希链完整性）+ 与上周周报锚对账（条数/头哈希必须单调）。
2. **逐件问**：档位可辩护吗？证据是空心的吗？回退真能跑吗？有同形件该收敛吗？
3. **反身性扫描**：本周有没有改动触及授权/审计/门禁/凭据/调度/知识层规则性条款？命中置顶。
4. **负空间问题**（每周必答）：**「本周该在账本里却没有的东西是什么？」**——防「静默什么都没发生」的假绿。
5. **收敛动作**（§6.4）：同形 → 结构件；`review_by` 到期 → 删/留；退役清单 → 删。
6. 出**三数报表**：新增 / 收敛 / 删除（补丁熵的唯一可测口径）。

### 6.3 人读周报（30 秒版式）+ 机械抽签

周报只一页，结论先行：**① 本周动作 N 件（其中自决 M 件、红队 REBUT x 件）② 异常/incident ③ 越权企图 ④ 我抽查了哪两条（附 60 秒可核对的证据行）⑤ 账本锚：条数 + 头哈希**。

**抽查样本由机械选样，不由 AI 挑**：`sample = 按 (n*2654435761 mod N)` 从本周账行里取 k 条（k 默认 2 或 10%，取大者）；auditor 与人都不参与选样——AI 选样 = 自选考题。人核完在周报回一行即可，人核出问题 ⇒ incident + 收紧。

### 6.4 反熵：三次法则 / 同形收敛 / Sunset（**执行者是 AI，不是计数器**）

- **同形收敛**：operator 一见到同形即可判「该收敛成结构」；auditor 每周必扫同形桶并出收敛卡（把 N 个补丁合并成钳夹/参数/枚举并删掉被取代者）。**不做机械计数器**（计数器是规则；判据是「三处同形补丁 = 一个缺失的抽象」这条原则）。
- **Sunset**：每件修复带 `review_by`（默认 90 天，防永久 workaround）；到期未证明仍必要 ⇒ **删除**（修复件是负债）。补偿性件（如 §8.2 的班次巡检补偿）必须带「根因修好后可删」的 Sunset 条件。
- **可测指标**（月度，写进成功度量）：`scripts/contrib` 净行数**不随修复数单调增长**；同形最大计数 ≤2；`review_by` 过期未处理 = 0；三数报表每周产出。

**与 v1 的差别一句话**：v1 靠**限速**（≤2 件/日）防风暴，v2 靠**可见 + 收敛**防熵。限速会挡住真需求，收敛不会。

## 7. 晋级与降级

### 7.1 凭证据晋级（ratchet：自动降、人工升）

| 阶段 | 内容 | 入口条件（可机械验证） |
|---|---|---|
| **S0 地基** | 机械层三件套上线（§4） | `contrib-ledger verify` rc=0；worker 侧 `gh pr comment` 被服务端拒且可 grep；回退演练真跑成功一次 |
| **S1 shadow** | 修复闭环全流程跑通，**但不上线**（产物+红队判词+账行都产，apply 人工点一次） | ≥5 件走完全链，0 件直接生效 |
| **S2 assisted** | 上线自动执行，观察窗 2 班 | 首件 auto 前：回退演练已跑；首件 auto 后：真回滚成功一次 |
| **S3 auto + 周审** | 常态化 + 每周 AI auditor + 机械抽签 | 首份周报交付用户并含账本锚；连续 2 周零 incident |

**「首次晋级由人拍一次」保留**（宪法升格制：人批一次成**边界**，之后同类不必再问）——这不算违背「减少对人依赖」，它批的是**授权范围**这条边界，不是日常动作。

### 7.2 自动降级与 kill switch（**AI 可自停，只有人能重启**）

- **AI 随时可自停**：冻结是「更保守的可逆项」，宪法明文允许自决。operator/auditor/fixer 任一发现异常都可置 `pipeline_fix.mode=frozen`。
- **机械/AI 触发的自动降级**：① 不可回退事故 → 立即 frozen + 全量冻结，**重启需人**；② 一个观察窗内 ≥2 次回滚 → 降 S1 + 冻结 N 日；③ 账本哈希链断裂 → frozen + 告警；④ 冷启动保护：连续 7 日零动作 + 零 incident 的「假绿」→ auditor 必须给出解释（不是自动降级，是必须解释）。
- **kill switch 两个独立开关**：`contrib-data/config.json` → `pipeline_fix.mode: shadow|assisted|auto|frozen`；环境变量 `PIPELINE_FIX_DISABLE=1`（车道直接拒跑）。任一命中即停。
- **重启权限的不对称是刻意的**：AI 能停自己，只有人能重启红线事故——因为「重启」是不可逆方向上的动作。

### 7.3 越权企图是资产

被 403 拦下的写企图、被红队 REBUT 的方案、被 auditor 判为「系统性低估档位」的件——**全部入周报数字**（不是被静默吞掉的日志）。它暴露的是模型想干什么，是唯一能提前看到漂移的信号。

## 8. 五个缺口的 v2 全程演示

### 8.0 缺口清单

| # | 缺口 | 层 | v1 的档位 |
|---|---|---|---|
| 1 | 到期钳夹：`?mode=ro` 竞态 + `watch-due:` 偏移解析脆弱（`2>/dev/null \|\| true` 吞失败） | 机制（读取/解析） | A3 + 六道闸 |
| 2 | 停放语义：`initial_status=blocked` 被 kernel 25s/10s promote；`scheduled` 无唤醒 actor | 框架/调度 | A4（恒人工） |
| 3 | `inventory.json` 无「载体已死」终态，且枚举已漂移出 `idea` | 机制（数据枚举） | A2/A3 边界 + 人拍一次 |
| 4 | 台账假阳性「in-flight ≠ 有货」（7 条零提交空壳） | 知识 | A1（已行使） |

### 8.1 缺口 1 —— 钳夹静默失败 + 偏移解析

- **发现**：operator 班内实查（journal 14:13；15:06 修正为「竞态型」——同刻 `?mode=ro` 有时成功）。症状不是报错，是**零事件**（`kind='unblocked'` 至今 0 条）。
- **诊断（根因句）**：一个函数里堆了两个根因，同源——**静默失败**（非零 rc 被 `|| true` 吞）与**字符串偏移解析**（`instr(...)+11,10` 遇双空格/散文即误判）。修法不是补窗，是让失败可见 + 用锚定正则替代偏移窗口。
- **修复（谁）**：operator 起 `[fix]` 卡（单关注点：`board_read()` + `parse_due()` 两个小函数），实现走 coder lane（mutation 自证 + 真库对拍），operator 不直接改文件。
- **红队（跨模型族）**：① `immutable=1` 的快照语义对「读到日→unblock」是否安全（会不会早醒/漏醒）② 还有谁依赖这个 SQL / 这个窗口（全仓 grep）③ **「解析不到」与「没有到期卡」必须可区分**（rc≠0 vs 空集）④ 失败语义：禁止再出现 `2>/dev/null || true` 形状。
- **自证**：同一真实 board 库上跑旧/新读法（4 张 scheduled 卡 rc 对照 4/4）+ 三种输入（正确 / 双空格 / 散文复述）+ mutation（改判据必红、还原必绿、`git status --porcelain` 归零）。
- **上线**：回退点 = commit sha（`git revert` 已核可达）；观察窗 2 班（到日是否真被 unblock；journal 有无 ⚠）。
- **账**：`shape=silent-failure-swallow` / `fixed-offset-parse`；`review_by` +90d。
- **对比**：v1 下这是「A3 甜区」但要过 6 道闸 + 白名单校验 + 80 行上限 + 变更预算扣 1 件；v2 下是 1 张 fix 卡 + 1 轮红队 + 1 行账。

### 8.2 缺口 2 —— kernel 停放语义（人门≠卡住）

- **发现/诊断**：journal 12:04（`scheduled` 是终止性停放、无唤醒 actor，源码 `kanban_db.py:3767-3790`）+ 14:11/14:18（`initial_status=blocked` 25s/10s 即被 promote）。根因在 **hermes kernel 的调度语义**，不在本域代码里。
- **v2 双路（关键演示：调度链属人门，但**不等于**无处可去）**：
  1. **本地补偿（AI 全权，域内可逆）**：班次 scheduled 列巡检 + 心跳钳夹到期 unblock（已上线，`git 8b2a379`）。这是 AI 在框架缺口下的**过程层自愈**——人没参与，且当场解决正确性风险。
  2. **根因修法转上游**：按本职流程走轴一（issue-first 证据 → PR），**这正是 KPI（commit 进仓）**。人门只挡住「改本机调度链」，不挡「修上游」。
- **红队**：补偿方案会不会**掩盖根因**（变成永久 workaround）⇒ 判据：补偿件必须带 Sunset 条件（「上游修好后删」），否则 REBUT。
- **账**：补偿件一行（`class=protocol`，带 `review_by`）；上游件走 L2，不入本账（它是轴一的事）。
- **一句话**：v1 把这条判成「A4 恒人工 ⇒ 只能等」；v2 把它判成「两路各归其位」——0 次人门，1 件真修复 + 1 件真贡献。

### 8.3 缺口 3 —— inventory 终态缺失（+ 枚举已漂移）

- **发现**：journal 15:06/15:20（`forge.sh:144` 枚举只有 ready/stale/in-flight/spent/needs-decision；实查 inventory 里**已有** `status=idea` 一条 ⇒ 枚举与现实已经双向不符）。
- **诊断**：下游把 `check` 的输出当「可能有货」消费，而载体已死的件只能停在 `needs-decision` ⇒ 假阳性朝**漏出手**方向偏。
- **修复**：① 扩枚举（加终态 `dead`，并收编已漂移的 `idea`）② 迁移既有漂移项（幂等、只改终态字段、保留原 commit 引用）。
- **语义裁定（取舍类 → AI 自决并留痕）**：`自决:台账必须能如实登记现实；dead≠spent（spent=被收编=KPI 正信号，混用会污染计数并抹掉情报差异）`。v1 把这条判成「policy，需人拍一次」；v2 判成原则内的取舍（诚实登记原则），**写进账，人从周报里纠**（用户纠的是原则，不是单条）。
- **红队**：① 谁消费 `status`（grep 消费者，`else` 分支会不会把 `dead` 误当 in-flight）② 迁移是否改写历史（必须只增终态、不许丢原引用）③ 有没有顺手把 `check` 改成观测态（**scope creep ⇒ 拆成缺口 4**）。
- **自证**：同一份 inventory 跑旧/新 `check`，diff 可见；迁移脚本重跑 0 变化。
- **账**：`shape=status-enum-drift`；同时沉淀一条判例（skill §3.2/§8，v1 08-29 判例已有同形条目）。

### 8.4 缺口 4 —— 台账假阳性（知识 → 机制，AI 自己升格）

- **发现**：知识层已自愈（skill §3.2 新增「forge 台账实查口径」，把 7 条空壳归类为立项欠账）。
- **v2 不停在知识**：追问「**为什么台账会说谎**」⇒ 根因 = `check` 报的是**声明态**（状态列），下游当**观测态**消费。结构修法：`check` 输出**观测事实**（`rev-list --count origin/main..<branch>` + worktree 干净度 + base 落后量），状态列降为注记。
- **这一步是纯 AI 自发的**：没有任何规则要求「知识修复必须升级为代码修复」——是 operator 按 P1（可逆性×爆炸半径）和 P3（治理靠原则）自己判的，判据写进账。
- **红队**：① 观测化的成本（git 调用次数）与失败语义（仓库不可达 ⇒ 必须标「未观测」，**不准**静默当「无货」）② 是否有下游依赖旧字段名（兼容期）。
- **账**：`shape=declared-vs-observed`；这条形状是**可复用原则**（「台账要回答消费者真正问的问题」），第 2 次出现即由 AI 判收敛，不靠计数器。

### 8.5 缺口 5 —— 隐藏耦合：机器行必须写在 comment

- **发现**：journal 14:05（钳夹 SQL 只扫 `task_comments` ⇒ 机器行写 body 读不到）+ 14:10（散文复述同 token 会被当日期 ⇒ 误判到期）。
- **v2 修法：把约定变成**可验证**的东西，而不是再写一条口径**：建 `[watch]` 卡后**立刻用钳夹自己的查询做一次 dry-run**（读得到日期才算卡建好；读不到当场报错）。**同一个 SQL 常量**供自验与实跑共用，禁止复制。
- **红队**：dry-run 与真跑路径是否一致（同一常量）；dry-run 失败时卡片是否留明确状态（不允许「静默建卡」）。
- **账**：`shape=hidden-coupling`；这是「约定 → 可验证」原则的第一个实例；若第 3 个同类出现，由 auditor 合并成**通用卡模板校验器**（AI 判，不设阈值）。

### 8.6 汇总：同一批缺口，两种做法

| | v1 | v2 |
|---|---|---|
| 动作数 | 2 补丁 + 1 人工拍板 + 2 零动作 | 域内自修 4 件（含 2 件结构性收敛）+ 转上游 1 件 |
| 人门次数 | 1（+ 每次要改白名单） | **0** |
| 机械层新增 | 6 道闸 + 白名单 + 方向表 + 哈希基线 + 速率计数器 | **0 个新脚本**（只多一本账 + 一个 verify 命令） |
| 结构性收敛 | 靠「同形第 3 次」计数器触发 | 靠 AI 判断 + 周审议程（本批已产出 2 件） |
| 长期单调性保证 | 限速（挡真需求） | 可见 + 收敛 + Sunset（可测） |

**诚实的代价**：v2 的**短期动作数更高**（4 件 vs 2 件）——因为知识修复会被 AI 主动升格为结构修复。这个代价是刻意的：它换来的是未来同类缺口的动作数下降（缺口 4/5 的形状一旦成结构，后续同形不再需要逐次打补丁）。是否值得，由 `scripts/contrib` 净行数与同形计数这两个可测指标每季度回答，不由本文件自证。

## 9. 失败模式：AI 审 AI 会怎么失效（含人的失败）

| # | 模式 | 机理 | 反制 | 谁负责发现 |
|---|---|---|---|---|
| 1 | **同谋盲区** | 红队与修复者共享同一错误框架（尤其同一模型/同一 context 的「自我复核」） | 换进程 + **只给产物不给论证** + 七问第 1/7 问强制换框 | 红队纪律本身；auditor 抽检档案 |
| 2 | **能力同源** | 不同模型仍共享语料与先验，某些框架对两者都不可见 | 跨模型族（降相关）+ **真库对拍（唯一与模型无关的证据）** + 人机械抽签抽查 | auditor（对拍证据是空心的吗） |
| 3 | **点头机器** | 长期 100% GO，复核仪式化 | GO/REBUT 分布入周报；「连续零 REBUT」是必须解释的信号 | auditor（固定质询项） |
| 4 | **审计者同化** | 周审 AI 与流水线长期共处，逐渐只报绿 | auditor 换模型族 + 负空间必答（「该在账里却没有的是什么」）+ 周报必须有数字锚（可被人一分钟核） | 人（读周报 + 抽签） |
| 5 | **自利漂移** | AI 修改约束自己的东西（授权/审计/门禁/知识层条款） | 反身性触发：红队必审 + 周报置顶 + 账本外部锚；六条红线原则里的人门 | 红队七问第 7 问 + auditor 反身性扫描 |
| 6 | **静默失败**（本域头号敌人） | 失败被吞、零事件被当正常（今天已 3 次实证） | 一切新机制必须声明失败语义且 fail-loud；auditor 每周扫 `2>/dev/null \|\| true` 形状与「零事件但应有事件」 | auditor + 症状复发率 |
| 7 | **人信任漂移** | 周报永远绿 → 人不读了 → 抽查失效 | 周报结论先行、带本周**最差**一件、抽查人核一条 <60 秒；人核出问题即 incident | 用户（唯一能判「我不信」的人） |
| 8 | **元层无穷** | 为审 AI 再建机制，机制又需被审 | 机械层封顶三件 + 周审一件；新增必须**替换**而非叠加 | 用户拍板边界 |

**残余风险的诚实声明**（不粉饰）：
- 上述反制**降低**而不消除失效概率。本设计的赌注是：**可逆性 + 全量可见 + 自动降级**把「AI 判断出错」的后果限制在「一次可回退的改动 + 一周内被发现」，而不是「不可挽回的损失」。凡后果超出这个界限的，都不在设计范围内（= 六条红线，走人门）。
- **AI First 不适用于对外动作**：轴一（L2）不是本设计要赋权的对象，本设计只加固它的地基（只读 token）。原因很简单——对外动作不可逆且涉及品牌资产，宪法已把它列为人门，这不是 v2 要推翻的条款。
- **AI First 也不是「AI 决定自己的边界」**：边界（六条红线 + 三件机械层）仍归人。AI 决定的是边界**以内**的一切。

## 10. 人在系统中的角色（重定义）

**只做四件事**：
1. **拍红线原则**（宪法层）：六条红线、三件机械层的改动权、升级到 auto 的那一次授权——**批边界，不批动作**。
2. **读一页周报**：30 秒，结论先行，带账本锚。不读单件、不审批日常修复。
3. **异常介入**：不可回退事故、kill switch 重启、抽签抽查、判「我不信」。
4. **持凭据**：签发/替换 token（唯一真正需要人的物理动作）。

**不再做的四件事**：逐条审批日常修复；维护/更新许可清单；挑抽查样本；当「缺口卡」的收件人。

**与 escalate 三理由的关系**：本设计**不新增** escalate 事由——①不可逆 ②预算 ③缺判断依据；六条红线原则是这三条在机制面的展开（不可逆/对外/凭据/删数据 = ①；额度调整 = ②；宪法层 = ③ 的授权面）。取舍类继续自决并留痕。

## 11. 分阶段路线

| 阶段 | 内容 | 入口条件（可机械验证） | 回退 |
|---|---|---|---|
| **W0 地基** | ① 凭据分离（只读 PAT + env seam，**唯一需要用户动手的一步**）② 回退通道 + `contrib-fix`/apply 工具 ③ `decision-ledger` + `contrib-ledger verify` | worker 侧 `gh pr comment` 被服务端拒（403 可 grep）；回退演练真跑成功一次；`verify` rc=0 | 删 env 注入 / 停用工具 |
| **W1 S1 shadow** | 修复闭环全链跑通（fix → 红队 → 账），**apply 人工点一次** | ≥5 件走完全链、0 件直接生效；红队协议与账行格式校准完 | 停建 fix 卡 |
| **W2 S2 assisted** | 上线自动执行 + 观察窗 2 班 | 首件 auto 前的回退演练已跑；首件 auto 后**真回滚一次** | `mode=shadow` |
| **W3 S3 auto + 周审** | 每周 AI auditor + 机械抽签 + 周报推微信 | 首份周报含账本锚并交付；连续 2 周零 incident | `mode=frozen` |

| **永不做** | 六条红线（不可逆 / 对外 / 凭据 / 删数据 / 调度链 / 宪法层）；框架改动走上游不走本地 | — | — |

**要不要动 hermes 框架？答：W0–W4 都不需要**（三件套全在 martin 仓 + 配置层）。唯一必须动框架的缺口（停放语义）恒属人门，且它的正路是上游 PR（§8.2）。

## 12. 我定不了的点（待用户拍板）

1. **「机制优化自留拍板」的收窄解释**（§1.1）：拍**边界**（红线/授权范围/三件机械层），不拍边界内的实现。这是本设计的地基，需你确认。
2. **只读 token 的落地路径**（唯一需要你动手的一步）：签发 GitHub 只读 PAT 并注入 contrib worker 环境；`approvals.deny` glob 是否同时保留作兜底（零成本，建议保留）。
3. **红队/auditor 的模型族固定**：建议 operator/fixer = deepseek-flash，红队与周审 = glm-5.3-flash 或 k3（跨厂商）。是否接受这个固定法。
4. **抽签比例**：默认每周 2 条或 10%（取大者），机械选样。是否接受，或你指定别的比例。
5. **周报通道与频率**：复用 digest 通道每周一次（建议周末），还是并入现有日报。
6. **首次晋级到 auto 的那一次人批**（§7.1）是否接受——这是本设计里唯一保留的人批。
7. **INDEX 登记**：本文件按仓规需在 `INDEX.md` 登记（v1 也未登记）；本卡红线只允许落盘设计稿 ⇒ 建议由交互会话补登记。
8. **本设计不改任何产线**：落地需另开实施卡（W0 的凭据分离是唯一需要你操作 GitHub 侧的一步）。
